# social-post — 訪談集的社群宣傳貼文

產出**一份企劃 → 兩種排版**：`fb.md`（可放連結、1,100 字）與 `ig.md`
（前 125 字定生死、連結在 bio、有 hashtag），另附 3 個替換鉤子讓修修挑開頭。

**這不是節目簡介，是「我經歷了一場對話」的第一人稱貼文。** 側寫實測：「我」密度
17.3／千字（比書評還高），「你」只有 1.97（幾乎不對讀者喊話，只自曝）。寫成
第三人稱的來賓介紹就是新聞稿，不是修修的貼文。

## 風格的單一事實來源

`data/brook/style-profiles-fable5/`，社群貼文的載入配方是**例外**：
`00 → 02 → 13 → 20 → 30`，**跳過 01-mechanics 的排版骨架**（13 §9 已逐條覆寫
01 的導言 blockquote／heading／粗體／連結密度／emoji 鐵律）。few-shot 用 13 §10
的 9 則，不是 21-exemplars。

本 skill **不重述側寫內容**，只規定流程；側寫改版時這裡不用動。

## 流程

### 0. 前置檢查

`data/brook/style-profiles-fable5/13-genre-social-post.md` 存在。不存在 → **停**，
告訴使用者側寫不在，先補側寫。不要憑印象硬寫。

### 1. 素材與 brief

| 欄位 | 來源 | 缺了怎麼辦 |
|---|---|---|
| 逐字稿 | `<episode>/transcript_prose.md` | **停**——沒有逐字稿不要寫 |
| 來賓姓名 | 使用者給 | 停，不從逐字稿猜 |
| EP 編號 | 使用者給 | `EP??` 佔位符 |
| Podcast／YouTube 連結 | 使用者給 | 佔位符，不要編網址 |
| 業配／合作揭露 | 使用者給 | 沒說就當沒有，**不要自己加** |

`transcript_prose_suspect.json` 若存在，先掃一眼——那是講者判定可疑的時段，
落在那裡的話**不要拿來當引言**。

### 2. 素材編號清單

把逐字稿拆成**編號清單**，之後的覆蓋復查全對著它。四類各自編號：

1. **來賓金句候選**——**逐字抄**，含口語質地，不准順成書面語
2. **來賓履歷錨點**——校名／公司／年份／書名／獎項／數字。側寫 §4a 實測平均
   26.8 個／篇，這是可信度的來源，**只能來自逐字稿**
3. **修修的個人錨**——他自己在訪談裡講的經歷、反應、自曝
4. **可量化的數字與研究**——研究名、百分比、年份

**⚠️ 模型知道這位來賓是誰。** 學經歷、著作、獎項一律**只能來自逐字稿**，
維基百科等級的補充是誠信紅線（20-negative §4）。逐字稿沒講就放佔位符。

**四種佔位符**（缺料時**放佔位符，不要省略**——省略掉整篇會變成沒溫度的摘要）：

| 佔位符 | 什麼時候放 |
|---|---|
| `【來賓素材：需要一個可查證的頭銜／數字／作品名】` | 履歷弧線缺一塊 |
| `【定位句：這位來賓在這個領域的地位？】` | 履歷走完的收束句（見 4b-4）|
| `【可掛讀者已知的概念：？】` | 出現需要白話化的概念時（見 4b-5）|
| `【修修的反應：？】` | 該有主持人評價的位置（見 4b-6）|

**完成判準**：清單編號化、報出總數；金句全部逐字。

### 3. 載入側寫

照 README 的社群配方 `00 → 02 → 13 → 20 → 30`，13 §10 挑 4–6 則對應槽位的範例
**攤在眼前寫**，不是讀過就丟。

### 4. 企劃（一次，兩平台共用）

照 13 §1b 的九拍骨架填空，每一拍指定要用清單裡的哪幾號：

```
[0] 標題行 EP##｜姓名：「金句」＋副標   [1] 開場報到
[2] 修修跟他的關係                    [3] 來賓履歷弧線（反差/低谷→轉折→成就）
[4] 亮點預告：給題目不給答案            [5] 議題化
[6] 修修自我回收                      [7] 商業揭露 ＋ CTA
[8] 收尾
```

⚠️ **第 [8] 拍有衝突，以修修的實改為準。** 側寫 §8a 從 5 篇語料歸納出「示範式
收尾：我自己要去做這件事」（df 5/5），但修修 2026-07-29 實改時把示範式結尾整段
刪掉，換成「留一個未回答的大問題 ＋ 誠摯推薦這集節目」。**這一版照他的實改做**
（見下面第 2、3 條）；但那只有 1 次證據，下一集再看是不是穩定。

**三個要當場定案的東西**：

- **標題行的金句**：從清單挑一句逐字的，不是自己寫一句
- **懸念用哪種機制**（13 §5 五型）：段落中間用**給足事實**型；**但結尾那一拍
  一定要藏**，見下面第 2 條
- **修修自我回收要回收什麼**：§6c 實測 5/5 篇都有一處自曝其短或私事

**完成判準**：九拍都有指定的素材編號，沒有一拍是空的。

### 4b. 修修 2026-07-29 實改回饋（八條，逐條照做）

第一版產出後修修親手改了一遍。這八條是從那份修訂 diff 歸納的，優先級高於
上面的骨架描述。

1. **每換一個話題，先寫一句「我問他 X」。** 這是修修唯一留註解點名的一條
   （「要加入這一句才有銜接啊」）。他加了四處：「我在訪談中也問他對腦科學是
   甚麼時候開始產生興趣的」「我請教授介紹他的新書」「當然我最好奇的，是老師
   如何看待 AI」「訪談最後，我問老師一題…」。
   作用有兩個：銜接，以及**把貼文錨回「這是一場訪談」**——不是我在整理知識，
   是我在現場問。沒有這句，話題之間會像剪貼。

2. **結尾必須藏答案，而且用它回收開頭的線。** 第一版把自由意志講完了
   （Libet 0.5 秒、誰決定舉手），修修整段砍掉，改成：
   > 訪談最後，我問老師一題書中只佔一點點篇幅，但其實貫穿了他這幾十年的問題：
   > 「人到底有沒有自由意志？」
   > 老師的回答相當精彩，也給了我很多啟發。
   只給問題、不給答案，而且「貫穿他這幾十年」把開頭「高中就在問生命的意義」
   那條線收回來。**收尾那一拍的懸念型別是 13 §5c，不是 §5a。**

3. **不要把自己的收穫講完。** 第一版結尾寫了「我現在坐捷運就發呆」「每天留一段
   空白」「生命的意義我還沒有答案」——修修全部刪掉。讀者拿到完整體驗就沒有
   理由去聽節目了。自我回收放中段，不放結尾。

4. **履歷弧線走完要有一句定位收束。** 第一版履歷走完直接跳新書，修修補了
   「於是教授抱持著對大腦的好奇和分享的熱誠，一路走到現在，成為台灣腦神經
   科學的權威，也是這個領域最著名的科普作家」。
   ⚠️ 「權威」「最著名的科普作家」**逐字稿裡沒有**——這是修修的外部知識。
   機器**不准自己寫**，要留 `【定位句：這位來賓在這個領域的地位？】`。

5. **把來賓的概念掛到讀者已知的框架上。** 修修在「生存機器／捷思」後面接了
   「這就是 "Thinking Fast and Slow" 的系統一。但有些事情我們一定要有意識地
   動用系統二」——**逐字稿裡沒有康納曼**。這是白話翻譯的另一種形式：不是解釋
   術語，是把新概念掛到讀者已經知道的東西上。
   同樣**不准自己補**，但要在該掛的位置留 `【可掛讀者已知的概念：？】`。

6. **主持人對內容的即時評價要留位置。** 修修加了「我看了真的覺得遇到知音啊，
   因為我之前在頻道中全部都有分享過」「我覺得超級有意思的」「老師的回答相當
   精彩」。
   注意跟「不要替修修把話講完」的界線：**訪談當下的行為與反應不可編造**
   （不能寫他當場跳起來、他點頭）；但**寫貼文時對內容的評價**是作者的權利，
   機器不知道他真的怎麼想 → 留 `【修修的反應：？】`，**不要因為不知道就省略**。
   省略掉整篇會變成沒有溫度的摘要。

7. **貼文引言允許最小順稿。** 修修把「那就發現一個問題，就是說好像看不到心靈
   是什麼」改成「所以我發現一個問題，我好像看不到心靈是什麼」，也把「那我就往
   最高的層次走**嘛**」的語尾助詞拿掉。
   **這與逐字稿的「一字不改」不同層**：`transcript_prose.md` 是證據層，貼文是
   傳播層。規則：可去贅詞、可補主詞，**不可改意思、不可換用詞**；順過的引言
   在交付時列出來給修修覆核。（lint 的引號回檔會 FAIL——順過的引言改用不帶
   引號的轉述，或在交付說明裡標注。）

8. **抓「具體到令人驚訝」的數字。** 修修補了「老師說他在新加坡生活的時候，
   竟然能夠早晚各坐一小時」——這在逐字稿裡有，第一版跳過了。挑素材時，
   **會讓人「蛤？」一下的數字優先**，勝過四平八穩的論點摘要。

### 5. FB 版

照企劃寫。機械層照 13 §7：1,100 字 ±200、19–30 段、一段一句是預設、
**段間用單獨一行 U+200B（不是空行）**、單段不超過 85 字。emoji 預設 0 個
（配額 0–1，只有寫到自己糗態時才給 1 個，只能是 🤣😓☺️）。

### 6. IG 版

**同一份企劃，不是另寫一篇。** 三處必改：

1. **前 125 字定生死**——IG caption 到這裡就被「⋯更多」截斷。鉤子＋來賓是誰＋
   一個具體錨點（數字／專名／引號金句）必須在這裡面講完，否則讀者連展開都不會
2. **連結不可點**——CTA 改成「連結在 bio」，正文不要放網址
3. **hashtag 有作用**——FB 版禁用，IG 版要加

### 7. 三個替換鉤子

再給 2 個不同切入的開頭（13 §2 的三型：身分報到／修修體感／不可思議的邀約），
**只換前 1–3 段，其餘共用**。理由：中後段是事實，四個完整版本內容一樣只是語氣；
決定成敗的是前兩行，選鉤子比選全文省時間。

### 8. 機械 lint

```
python .claude/skills/social-post/scripts/social_lint.py <fb.md> --platform fb \
    --source <episode>/transcript_prose.md
python .claude/skills/social-post/scripts/social_lint.py <ig.md> --platform ig --source ...
```

擋：字數／段落／空行／U+200B／emoji 白名單與配額與位置／markdown 殘留／分號／
禁用詞（42 詞黑名單，直接 import 側寫的 `verify_quotes.ZEROS`）／AI slop 句型／
簡體字／連結數／hashtag／IG 截斷點／佔位符／**引號逐字回檔**。

**FAIL 一定要修掉再交。** WARN 逐條判斷（例：`不是 X，而是 Y` 是 WARN 不是 FAIL——
修修自己的 fb-interview-5 用過一次）。

引號回檔 FAIL 有一個合法例外：**照 4b-7 順過的引言**。順稿的引言不要包在「」裡，
改用不帶引號的轉述，並在交付說明列出「哪幾句順過、原話是什麼」給修修覆核。

### 9. 冷讀者驗收（這一層不能省）

2026-07-05 財富階梯 postmortem 的根因二：**review 方法認證了爛文案**。persona 被
寫得太聰明、太願意買單，rubric 只要「有行動」就給分，judge 用分析師腦讀完全文。
分數該給 20–30 的給了 70–86。

所以派 subagent 當**冷讀者**，規格寫死：

- **當純文字評**，不看排版、不看配圖（postmortem：渲染成品會讓分數虛高）
- **滑手機腦，不是分析師腦**：一則 0.5 秒，看不懂就走。**逐段問三個問題**——
  「這跟我什麼關係」「這什麼意思」「所以呢」
- 回報格式：**在第幾段決定不點開節目、為什麼**。不要給總分，要給流失點
- 專門查：未定義的術語、沒有動機的宣稱、不可信的誇大、跟 TA 無關的鉤子
- IG 版**只讀前 125 字**評一次，再讀全文評一次

冷讀者說「在第 N 段流失」→ 回第 4 步改企劃，不是改字。

### 10. 交付

寫到 `<episode>/repurpose/`：`fb.md`、`ig.md`、`hooks.md`（3 個替換鉤子）。
交付訊息要列：素材覆蓋率、lint 結果、冷讀者的流失點、**所有佔位符**（4b 那四種
是給修修填的，不是瑕疵）、**順過的引言清單**（哪幾句、原話是什麼）。

**交付前先跑 `.baseline/` 快照**：`repurpose/.baseline/` 留一份原稿，修修改完之後
才 diff 得出紅線。沒有快照就等於沒有回饋迴路。

## 原則

- **零 API 錢**：全程 subagent，不打付費 API
- **具體 > 抽象**：專名密度 23.9／千字是可信度來源；形容詞不是被禁是被上鎖
  （側寫 §4b：主力是「最」，每次後面跟一個可查證的名詞）
- **不要替修修把話講完**：逐字稿裡沒有的反應、感受、身體動作一律不寫
- 舊的 `agents/brook/fb_renderer.py` / `ig_renderer.py`（第一代，付費 API +
  先摘要再擴寫）已退役，不要呼叫
