# youtube-side-bullets — 重點條列

**版本：v1.0（2026-11-16）**

YouTube 照稿影片的 DP 由一類一類的小 skill 組成（已有 `youtube-concept-title`、`youtube-book-cover`、
`youtube-person`、`youtube-reframe`、`youtube-chapter-card`、`youtube-section-title`、`youtube-quote-card`）。
重點條列由 Director 提、修修在 Bridge（`/bridge/video-plan/<episode>`）核准；本 skill 只負責把
**已經核准**的列做成素材，不改時機、不改字。

修修 2026-11-16 提出：「我想做一種是側邊的條列式 bullet point 的動畫。比如我在解釋某一個主題的總結，
像是財富階梯最後面的 5 個總結的時候，可以把我人移到一邊，然後另一側就用 bullet point 的方式一個一個列出來」。

## 設計（修修逐輪定版，不要自己改）

| 元素 | 定版 | 修修原話／來源 |
|---|---|---|
| 版面 | 右側品牌冷灰 `#dddddb` 實色側欄（x≥1110，左緣斜邊），從右滑入 0.5 秒；人由畫面搬移 `left` 讓到左 1/3，同一秒開始 | 三款（深色側板／白色字牌／品牌灰側欄）選「品牌灰側欄」：「我喜歡第三個」 |
| 字 | 左上橘色斜邊字牌「重點整理」；每條黑色思源黑體 Black 44px，太長自動平衡換行（最多 2 行）；每條在它那句字幕開頭從右滑入 | — |
| 編號 | 橘色 60px，**數字底部跟第一行字底部切齊**（往上移 6px，實測） | 「標題的數字跟文字沒有對齊」→「數字跟文字的底部應該是要在同一個 level」→ 試 64／60／44px 選 60px |
| 品牌元素 | 品牌手冊 `brand-identity.pdf` 第 24 頁「影片開頭」右下角貼著底邊的 3 塊橘色碎片（章節卡 POLYS 第 4、5、6 塊，原樣不重畫；跟金句卡同一組），從畫面下方探進來，往下推 110px 只露一截 | — |
| 退場 | 結束前 0.5 秒字淡掉、碎片縮回；結束前 0.35 秒側欄滑出（0.3 秒），最後一格前完全離開（畫面搬移在結束前 0.25 秒開始退回） | — |

被否決過、不要再提的方向：深色側板（新的一條出來時前面的變淡）、白色字牌一條一條拍上；
編號 64px（數字比字高一截）、44px（跟字同大）、編號跟字中心對齊。

元件原始檔：`video/compositions/side_bullets/compositions/side_bullets.html`（多邊形座標已內嵌）。
改設計＝改這一份，並在 PR 附渲染截圖給修修看過。

## 側欄上放什麼

- **條列**＝「畫面上的字」（`onscreen_text`），**一行一條**，照講的順序。
  - 行首的「1.」「2、」「-」「・」會拿掉（編號由元件加）。
  - 寫成精簡的重點（例：「花錢看階層，用萬分之一法則」），不是整句逐字稿。
  - 每條最多排成 2 行（每行約 13 個全形字，半形算 0.55）；最多 6 條；整份太高會碰到右下碎片，也擋下。
- **標題**固定「重點整理」（要換字是之後再加的功能，目前沒有欄位）。

## 時間

- 整張：從這一列蓋住的第一句字幕開頭，到最後一句結尾（3–60 秒）。建議從「再幫大家整理一下幾個重點」那句開始，
  到最後一條講完那句結束。
- 每一條在哪一句出現（程式自動，不用填）：
  1. 在這段字幕裡**依序**找「第一」「第二」……（也認「第1」「第１」）。找齊了，第 N 條就在講「第 N」那句的開頭出現。
  2. 沒找齊（例：講法是「首先」「再來」），就把條列平均分配到這段字幕的句子開頭——指令會印「平均分配」，
     要更準就請修修在 Bridge 調字幕範圍或改講法對應的條數。
  - 第一條最早在側欄滑到位（0.6 秒）之後；最後一條至少要在畫面上停 1 秒，否則擋下請把字幕範圍往後拉。

## 怎麼跑

```bash
python -m agents.brook.youtube_video.visuals.side_bullets "G:/Footages/<episode>"
```

- 只渲 `category == side_bullets` 且 `status == approved` 的列；`--row <id>`、`--force` 同其他元件。
- 一張約 1.5 分鐘（元件固定渲 60 秒再截）。條列、時間、秒數與元件沒變就沿用。
- 畫面搬移：`python -m agents.brook.youtube_video.visuals.reframe` 依收據自動排 `left`（見 `youtube-reframe`）。

## 交件（所有分類共用的格式，`agents/brook/youtube_video/visuals/delivery.py`）

- `<episode>/visuals/<row_id>.mov`：1920×1080、29.97 fps、ProRes 4444 帶 alpha，長度＝停留秒數。
- `<episode>/visuals/<row_id>.json`：收據；變數（條列、每條秒數、停留秒數）、`start_sec`、`duration_sec`、
  `item_timing`（`ordinal`＝對準「第一…」／`even`＝平均分配）。

## 驗收

1. 指令最後一行是 `N/N 張完成`；有 ✗ 的列回報給修修（通常是太長、太多條或字幕範圍太短）。
2. 用畫面搬移預覽疊上去看：臉在左 1/3 沒被側欄蓋到、每條出現對得上講到第幾點、字沒碰到右下碎片、
   退場時側欄跟臉一起回去、最後一格沒有殘影。
3. `ffprobe` 確認 `prores 4444`、`yuva444p`、`30000/1001`、長度對。

## 還沒定

- 標題換字（例：「三個步驟」）：目前固定「重點整理」，要用到再決定放哪個欄位。
- 「首先／再來／最後」這類講法的對時：目前落到平均分配。
