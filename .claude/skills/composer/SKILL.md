# composer — 把素材寫成修修聲音的長文初稿

產出是**聲音初稿（voice draft）**：結構、論證、聲音都到位，修修只做刪改與定稿。
與 `/draft-article` 的分工：它出「理性骨架，句子層留白」；composer 出「整篇都是修修的聲音」。兩者並存，甚至可以串接（骨架 → composer 上聲音）。

執行分成三個 pass——**結構 pass（節拍骨架）→ 聲音 pass（逐節成文）→ 驗證 pass（機械 lint ＋ 自審）**。
不要一口氣從素材直接寫成品：結構與聲音分開處理，長文才不會中段漂移；lint 擋機械層、自審擋聲音層。

## 風格的單一事實來源

`data/brook/style-profiles-fable5/`——人設（00）、機械層（01）、語彙劑量（02）、三文類節拍（10/11/12）、禁區（20）、逐字範例（21）、生成協定（30）。
本 skill **不重述側寫內容**，只規定流程；側寫改版時這裡不用動。

## 流程

### 0. 前置檢查

確認 `data/brook/style-profiles-fable5/README.md` 存在。不存在 → 停，告訴使用者側寫不在、先補側寫。
**完成判準**：README 讀到了載入配方表。

### 1. 分流（素材型別 → 文類）

| 素材 | 文類（載入的 playbook） | 素材來源 |
|---|---|---|
| literature note（讀書筆記） | book-review（10） | `KB/Literature/<slug>.md`＋`KB/Annotations/<slug>.md`，或使用者貼上 |
| 訪談逐字稿 | 預設 people（11）；若目的是「把來賓的知識整理成教學長文」→ science（12） | 檔案路徑或貼上 |
| 課程大綱／教學素材 | science（12） | 檔案路徑或貼上 |
| 理性骨架（draft-article 產物） | 沿用骨架既有結構，文類依內容判 | `AgentOutputs/brook/drafts/` |

逐字稿要先問一次目的（人物故事 vs 知識整理），其他型別有歧義才用 AskUserQuestion 問，否則直接判。
**完成判準**：文類定案並說出理由（一句）。

### 2. Brief（個人錨素材是命門）

照 `30-generation-protocol.md` §1 的 brief 模板收集欄位。兩個欄位特別處理：

- `personal_material`（修修的親身經歷／數據）：**這是修修文章的靈魂**。素材裡沒有 → 向使用者要一次；使用者說先跑 → 進入佔位符模式（下一步照常，缺錨處全部佔位符，見 30 §2）。
- `current_facts`（時效事實：訂閱數／年齡／業配狀態）：沒給就一律佔位符，**絕不**沿用語料舊值。

**完成判準**：brief 欄位全數有值，或明確標記「佔位符模式」。

### 3. 素材編號清單（覆蓋度的依據）

把素材拆成**編號清單**，之後的覆蓋復查全對著它。各型別的拆法：

- literature note：每條 `note::`（使用者論點）＋每段畫線（書的論據）各一號。
- 逐字稿：來賓金句候選（**逐字抄**，含口語質地）、故事節點、可量化的數字神蹟，各一號。
- 課綱：每個單元／論點一號，並標注「此論點需要文獻支撐？」——需要而素材沒給 → 記為佔位符號。
- 理性骨架：每個 H2 節與其論據各一號。

**完成判準**：清單編號化、報出總數；逐字稿的金句候選全部是原文照抄。

### 4. 載入側寫配方

照 fable5 README 的配方：`00 → 01 → 02 → 對應 genre → 20 → 21 挑 4-6 則對應槽位 → 30`。
21 的範例要挑**本次會用到的槽位**（開場型、個人錨、白話翻譯、收尾……），攤在眼前寫，不是讀過就丟。
**完成判準**：列出本次選用的範例編號（如 A2/A3/B4/A8）。

### 5. 節拍骨架（結構 pass）

照 genre playbook 的節拍排 beat sheet。每一節寫三行：**功能**（在節拍結構中的角色）、**吃哪幾號素材**、**個人錨用哪條**（或標佔位符）。
標題與導言（hook）各出 **2-3 個版本**（公式見 01 §10 與 genre 開場鉤分型），正文只出一版。

**完成判準（窮盡）**：素材清單**每一號**都被分配到某節，或明確標「捨棄＋一句理由」；每個主要節都有個人錨或佔位符；字數配額加總 ≈ brief 目標（無指定則用 01 §11 文類均值）。

### 6. 逐節成文（聲音 pass）

沿骨架逐節寫。每節的紀律：

- 結構跟 playbook 節拍，聲音跟 21 範例，**劑量跟 02**（助詞、台語 punchline、招牌詞都有劑量上限——招牌用過量是拙劣模仿）。
- 保留素材的具體性：來賓說「龍氏蛋」就不要抽象成「蛋」；具體就是口吻。
- 每寫完 2-3 節，回讀骨架＋用一句話 recap 已寫各節，再繼續——長文防漂移。
- 紅線（見 20 §4，違反＝整篇作廢）：個人經歷／數據只能來自 brief 或素材清單；來賓語錄逐字；研究引用只能用素材裡的來源；缺料寫佔位符，不腦補。

**完成判準**：全部節寫完；每節都能指出用了哪幾號素材。

### 7. 機械 lint（驗證 pass 之一）

```bash
python .claude/skills/composer/scripts/style_lint.py "<draft路徑>" --genre <book-review|science|people>
```

退出碼 1 = 有硬傷（禁用詞、emoji、簡體字、殘渣、段落過長、聲音過平或過載）→ 修到 exit 0，不跟 FAIL 討價還價。WARN 逐項判斷並說明去留。

### 8. 聲音自審＋覆蓋復查

lint 只擋機械層；這一步過語意層（30 §4b/4c）：

- 對素材清單逐號打勾：進稿的標節次、捨棄的有理由——**一號都不能默默消失**。
- 30 §4b 聲音清單逐條過（每個觀點有錨、機制後有人話、括號旁白 3-6 個、收尾組合拳完整……）。
- 盲測自問：刪掉署名，隨機抽三段，分得出是 AI 還是修修嗎？分得出 → 指出哪段、為什麼，改掉。

**完成判準**：素材覆蓋表完整；4b/4c 逐條標注通過或修正；盲測自問有明確答案。

### 9. 落檔交付

```
$VAULT/AgentOutputs/brook/drafts/<slug>-voice-draft-<YYYY-MM-DD>.md
```

frontmatter：

```yaml
---
title: "<標題版本一>"
title_alts: ["<版本二>", "<版本三>"]
source: "<素材出處（slug 或檔名）>"
draft_mode: voice-draft
draft_status: draft
generated_by: composer
style_profile: fable5
---
```

交付訊息包含：草稿路徑、lint 結果、**佔位符清單**（等修修填的東西，逐條列出）、標題／導言版本、素材覆蓋摘要（用了幾號／捨棄幾號）。
Provenance 單向：只讀 KB，**絕不**回寫 `KB/`，不碰 `Journals/`。
