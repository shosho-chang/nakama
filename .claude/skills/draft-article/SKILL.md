# draft-article — 把一本書整理成理性的原子文章骨架草稿

把一個**已經 ingest 進 KB 的 source**（書／文章），整理成一篇**理性、低修飾、但讀者讀得下去**的
長文骨架。輸出是 **draft（骨架初稿）**：先想讀者、給 Hook，再把書的論點 ＋ 使用者**所有**的論據，
展開、舉例、乾淨陳述。

**核心分工：skill 出「策略結構 ＋ 完整理性骨架」，使用者加「句子層的情緒口吻」。**

- skill 負責：① **讀者分析**（TA ＋ 為什麼看下去）；② **3 個 Hook**；③ 理性、**逐條覆蓋 annotation**、
  展開舉例的完整骨架，含「讓讀者一節一節讀下去」的論證弧。
- 使用者負責：句子層次的情緒、台味口語、自嘲、最終潤飾與段落打磨。
- 界線：skill 做**策略層的起承轉合**（Hook、讀者留存的論證弧、每節「為什麼這對你重要」），
  但**不寫句子層的情緒 ornament**（台味助詞、emoji、浮誇形容詞）——那是使用者的。
- 為什麼這樣分？草稿是給人接著大改的；句子層硬套聲音反而蓋掉使用者的語感、更難改。但**沒有
  Hook、沒讀者意識、又把 annotation 砍成摘要**的骨架，會又短又平、沒人想看。兩個極端都要避開。

書 ＝ 論據，使用者的 `note::` ＝ 論點。這個 skill 的價值在於：**先替讀者著想、忠實萃取書的邏輯、
把使用者埋在 note 裡的論點一條不漏地浮出來並展開、且絕不虛構**——而不是模仿文筆。

## 流程

### 0. 解析輸入 → slug

```bash
VAULT=$(python -c "from shared.config import get_vault_path; print(get_vault_path())")
ls "$VAULT/KB/Literature/" | grep -i "<關鍵字>"
```

- 唯一命中 → 用它。多個 / 找不到 → 列候選問使用者，別猜。
- Literature Note 不存在 → 告訴使用者「這本還沒 ingest，要先 /ingest」，停。

### 1. 載入素材（KB，唯讀）

| 檔案 | 角色 |
|---|---|
| `KB/Literature/<slug>.md` | **主骨**：逐章「畫線（`>` 引用）＋使用者 `note::`」。`note::` 是論點來源。 |
| `KB/Annotations/<slug>.md` | 完整畫線/註解 store，查證用 |
| `KB/Raw/...<slug>...` | 全書／全文原文，查證特定數據、補沒畫到但需要的脈絡 |

> ⚠️ Literature Note 結尾的 `## 🔗 KB 相關（AI 撈，FTS5）` 區段常常整片是「（無 KB 命中）」
> —— 死區雜訊，compose 時完全跳過。

### 2. 盤點兩條素材線（不載入聲音側寫）

理性模式**不套風格側寫、不讀 `agents/brook/style-profiles/`**。改成盤點：

- **書的邏輯骨架**：主要論點 / 框架 / 數據有哪些？（決定 H2 結構）
- **使用者的論據（關鍵）**：把 Literature Note 裡的 `note::` **逐條抄成編號清單**（可用
  `grep -c "note::"` 先數總數）。這份清單是後面「覆蓋度」的依據——**理性 ≠ 精簡，一條都不能漏。**

### 3. 讀者優先（compose 前必做，先想再寫）

動筆前先回答這三題，並把答案寫進交付的最前面：

- **TA 是誰**：他的處境、他的**願景**（他真正想要的結果，要有畫面感）、他的痛點。
- **他為什麼要看下去**：這篇給他的**具體 payoff** 是什麼？（不是「了解這本書」，是「拿到一張能用的地圖」這種）
- **怎麼一張一張留住他**：每節開頭先點出「你現在的做法為什麼推不動 / 你還缺什麼」，再給解法——
  讓每節結尾都欠讀者一個「那到底該怎麼辦」，逼他翻下一頁。**給足理由，別假設他會自己讀完。**

### 4. Hook（產出 3 個版本，置於正文最前）

交付時在正文最前提供 **3 個 Hook 版本**供使用者擇一。每個 Hook 走這條已驗證的開場弧：

1. **描述 TA 的願景**——他想要的結果，有畫面感。
2. **點出傳統、被普遍相信的做法**——穩定工作、努力升遷、省錢、買房……
3. **讓讀者覺得這做法「似乎行得通」**——誠實承認它過去確實有效。
4. **轉折：但這條路在今天的世界，對多數人已經被阻斷了**——給出為什麼（薪資天花板、通膨、資產膨脹…）。
5. **帶出本文／本書要給的「科學方法 / 新地圖」**作為出路。

3 個版本用**不同入口**（願景型 / 數據驚詫型 / 問題重構型…），但都走完這條弧。
Hook 是策略結構、不是情緒 ornament——一樣保持理性、不撒台味助詞 / emoji。

### 5. 掃 KB Wiki 撈補充事實（選配）

```bash
grep -rl "<關鍵概念>" "$VAULT/KB/Wiki/Concepts" "$VAULT/KB/Wiki/Entities"
```

撈相關 Concepts / Entities 當補充事實。**只能正向引用（KB → 草稿）**，素材不足就跳過。

### 6. compose 理性骨架

依**書的邏輯**搭 H2 結構（一個主題一節）。每節：①陳述書的論點（理性、附必要數據）→
②接上使用者相關的 `note::` 論據（以陳述句寫出他的立場/反駁/補充）。

紀律（違反任一 = 失敗）：

- **第一守則：逐條覆蓋 Step 2 清單裡的每條 `note::`。** 理性 ≠ 精簡；不要把 annotation 砍成摘要。
  寫完對著清單檢查，確認沒漏。漏掉使用者的 note = 漏掉這篇最有價值的部分。
- **展開概念並舉例**，不要只丟一句結論就過。大部分例子就在 annotation 裡（具體的生活情境、數字）。
- **保留使用者的具體**：他寫「龍氏蛋」就別抽象成「蛋」、寫某公司名就別寫成「科技公司」——
  **具體就是他的口吻**，抽掉就平了一截。（具體事實若與其他來源有出入，標記出來問使用者，不自行抹平。）
- **理性銜接、不寫句子層情緒/口語**（台味助詞、emoji、浮誇形容詞、自嘲）——那是使用者的工作。
  （策略層的 Hook 與論證弧是 skill 的工作，見 Step 3–4，兩者不衝突。）
- **絕不虛構**：每個個人立場 / 數字 / 經歷都必須對得到某條真實 `note::` 或 source。寧缺勿造。

### 7. 寫到 Output（非 KB）

```
$VAULT/AgentOutputs/brook/drafts/<slug>-draft-<YYYY-MM-DD>.md
```

frontmatter：

```yaml
---
title: "《<書名>》介紹草稿（理性骨架）"
source: "[[KB/Literature/<slug>]]"
draft_mode: rational-scaffold
draft_status: draft
generated_by: draft-article
---
```

正文順序：**讀者分析（TA＋為什麼看下去）→ 3 個 Hook → 理性骨架本體**。
（`AgentOutputs/brook/drafts/` 不存在就建。日期用 `date +%F`。）

### 8. 跑理性骨架 lint ＋ 自審

```bash
python .claude/skills/draft-article/scripts/lint_draft.py \
  "$VAULT/AgentOutputs/brook/drafts/<檔名>"
```

退出碼 1（FAIL）= ornament 滲入（emoji、台味助詞 >8、驚嘆號過多），代表句子層退回去模仿聲音了
→ 清掉、回到理性，重跑 lint 直到無 FAIL。lint 同時印語意自審 checklist。交稿前再加查：

- □ 正文最前有 **3 個 Hook**，每個都走完整開場弧（願景→傳統做法→看似可行→已被阻斷→新地圖）
- □ Step 2 清單裡**每條 `note::` 都覆蓋到了**，沒漏
- □ 使用者的**具體例子有保留**（沒被抽象成通稱）
- □ 每節都有「為什麼這對讀者重要」的拉力，不是平鋪直敘

### 9. 交付

交草稿路徑 + lint 結果 + 一句話：**「這是理性骨架（含讀者分析＋3 Hook），句子層的情緒/口吻/最終
潤飾請你自己接。」** 並指出哪些是書的論點、哪些是從使用者 note 浮出來的論據。

## 硬邊界（絕不踰越）

- **只出理性骨架，不出句子層聲音。** 不套風格側寫、不加句子層情緒口語——那是使用者的工作。
  （Hook 與讀者留存的論證弧屬策略結構，是 skill 該做的，不算違反。）
- **Provenance 單向**：只能 KB → 草稿。**絕不**回寫 `KB/`（Literature / Raw / Annotations / Wiki）。
- **絕不虛構**個人經歷 / 數字 / 立場——每一條都要對得到真實 `note::` 或 source。
- **不碰** `Journals/`。
- **不定稿、不發布、不潤色成成品。**
