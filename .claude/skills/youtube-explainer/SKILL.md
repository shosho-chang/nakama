# youtube-explainer — 解釋動畫

**版本：v0.4 草稿（2026-11-17：改成不分題材的三個決定；五個型態有原型；主角畫風待修修定）**

## 為什麼是兩層，不是一句 prompt

HyperFrames 不讀文字 prompt，它把一頁網頁（HTML＋GSAP）逐格渲成影片——寫網頁的是 agent。
所以「怎麼下 prompt」其實是兩件事：

1. **Director 的解說需求**（規劃表「給 DP 的指示」）：要觀眾懂哪一句話，以及下面「三個決定」各選了什麼。
2. **DP 的手冊**（本文）：只准用品牌積木組、清楚度規則、驗收方法。

品牌一致不能靠在 prompt 裡寫「要有品牌感」——每支各自發揮就會各長各的（重點概念 title 第一輪四版全被否決就是這樣）。
做法是**封閉的積木**：底板、碎片、標題、出處、進退場、「講到哪個亮哪個」、數字跳動全在
`video/compositions/explainer/assets/kit/`，每個型態一個模板，DP 平常只填內容 JSON，不寫新的 HTML。

## 三個決定（任何題材都一樣）

修修 2026-11-17：「我們需要的是一個可以解釋動畫、比較 general 的指令，所以它以後不論是解釋這種階梯，
或是解釋其他的情境，甚至解釋運動，都可以用得上。」——所以這裡只寫**怎麼決定**，不寫某個題材怎麼畫；
具體長相是下面「積木」的事。

### 1. 結構：照「這個想法的形狀」選型態，不照題材選

先問：觀眾要懂的那一句，是哪一種形狀？

| 想法的形狀 | 型態 |
|---|---|
| 幾個數量各佔多少、誰比較多 | 比例 |
| 拿實際數字算一次 | 算式 |
| 兩組東西對照 | 對比 |
| 一組並列的屬性 | 面板 |
| 有先後順序的等級、位置 | 階梯／刻度 |
| 隨時間變化 | 曲線 |
| 步驟、因果、A 導致 B | 流程 |
| 身體怎麼動、姿勢對錯（運動、動作） | 動作示範 |

同一個題材可以是不同形狀：「財富」可以是比例（資產組成）、階梯（六個階層）、曲線（複利）。
選錯形狀，畫得再生動也講不清楚。

### 2. 主角：畫面裡有沒有「誰」在動（選用）

- **沒有主角**：數字、結構本身就夠清楚時（大部分的比例、算式、對比）。不要為了熱鬧硬加。
- **物件當主角**：錢、球、積木……被搬動、變多、流走、卡住。適合「錢跑到哪裡去」「東西怎麼累積」。
- **人當主角**：要觀眾代入「自己在哪裡、會怎樣」，或要示範身體動作時。

有主角時，它做的事全部從稿上那一句來：
- **場景＝稿上用的比喻**（稿說「RPG 角色面板」就是狀態視窗、說「階梯」就是樓梯、說「一把尺」就是尺）；稿上沒有比喻就用型態本身的版面，不自己發明比喻。
- **動作＝那一句的動詞**（「爬上第六階」→ 往上跳；「外表看不出來」→ 面板收起來；運動的「雙手舉過頭」→ 手臂往上舉）。
- **道具＝那一句的名詞**（「超市想買什麼就買什麼」→ 推車；「想去哪裡玩」→ 飛機）。
- 不對任何一句的動作不加：待機就是待機，不加晃動、飄浮、表情變化。
- **故事可以有，但要寫出來**：成片 RPG 段落的「季節變換、角色變老、LV 升到 99」是故事，不是稿上的事實。
  Director 想用就寫進拍點，修修看過才做；數字照樣只能來自稿（LV、數值這種示意數字也不編）。

### 3. 分幕：一次多長、什麼時候回到修修

修修 2026-11-17：「整個解釋的時間太長，中間一定要穿插回到我的 talking head。」

- **滿版一次不超過約 15 秒**（成片 RPG 段落是 15 秒；原型「財富階梯」一口氣 70 秒，太長）。超過就拆成幾幕，
  幕跟幕之間回到修修（或原本規劃的空景）。——15 秒是提議值，等修修看過幾支再定。
- **下一幕從上一幕最後的樣子接著長**（例：第二幕一進來，前兩階已經在那裡），觀眾不用重新認一次畫面。
- **疊加版（右側側欄，臉還在左邊）可以比較長**：要一路累積、但不需要整個畫面的內容，優先用疊加。
- 一幕只推進一步：一幕講完一個「階」、一個項目、一個步驟，就該回到人。

## Director：解說需求怎麼寫（「給 DP 的指示」）

```
懂了什麼：錢只是人生面板上的一個數值，其他數值外表看不出來但都重要
型態：面板
主角：人（修修）——站在面板左邊
分幕：一幕（807–823 秒，約 15 秒，滿版）
拍點：
- 389「我還是會想用RPG來做比喻」→ 主角走進來，面板出現
- 390「錢只是你角色面板上的一個數值」→ 金錢那列亮起，主角頭上冒出金幣
- 391–392 經驗值、技能值、體力值、人際關係值 → 各自那列亮起＋對應圖示
- 395「這場遊戲的外表是看不出來」→ 面板收起來，只剩主角
- 396「但每一個都超級重要」→ 面板彈回來，整組亮起（重點，停 2 秒以上）
數字：無（稿上沒有數值 → 量表一樣長，不畫成數字）
```

- **懂了什麼**只能一句。一支動畫只講一件事；兩件事就開兩列。
- **型態、主角、分幕**照上面「三個決定」寫；主角寫「無」也要寫出來。
- **拍點**用字幕的句號（cue id）＋那句的原文，寫「這句出現／改變／主角做什麼」。說到才出現——不要一開始就全擺上。
  分成幾幕時，每一幕各列一組拍點，寫清楚中間回到哪裡。
- **數字只能來自稿或字幕**，寫出在稿上哪裡。要「實算」的（例：複利）把**假設**一條一條寫出來
  （本金、報酬率、年數），DP 用程式算，不心算；**稿上沒有的情境（例：25 歲 vs 35 歲）不能自己編**，
  在「備註」寫「需要修修提供／確認假設」，修修沒點頭不做。
- 「出處」欄要填（畫面右上角會印）：書名、報告名。
- **沒有數字就不要畫出數字的樣子**：量表、長條的長短會被看成數值。稿上沒有數字時一律一樣長，或拿掉量表。
- **最後一拍要停 2 秒以上**：重點落在最後一句時，把 `end_cue` 往後延一句（不跟下一列重疊）。

## 積木（DP 用的現成零件）

品牌一致靠這些積木，不靠每支各自小心。沒有合適的積木時**不要自己寫一支新的**：在備註寫「需要新積木」，
跟修修討論設計（跟其他分類一樣一個一個定版）。

**型態模板**（`video/compositions/explainer/compositions/`，填內容 JSON 就能渲）

| 型態 | 模板 | 狀態 |
|---|---|---|
| 比例 | `proportion.html`：白色軌道＝100%，填進去的是比例 | 原型 |
| 算式 | `equation.html`：一行一行貼上，結論斜貼白牌 | 原型 |
| 對比 | `contrast.html`：兩欄白牌，中間黑線；最後的重點把一項再點亮、貼斜黑牌 | 原型 |
| 面板 | `panel.html`：白底黑粗框的狀態視窗，每列標籤＋量表；可加主角、面板收起／彈回 | 原型 |
| 階梯 | `ladder.html`：講到第幾階就長出那一階，主角跳上去、冒出代表物 | 原型（**還不能分幕**，下一步） |
| 刻度 | — | 未做（例：模糊的問題變成一把尺——那兩句字幕有缺字，要先聽過） |
| 曲線 | — | 未做（例：複利曲線——假設待修修給） |
| 流程 | — | 未做 |
| 動作示範 | — | 未做（運動：需要能動關節的人物，像素做不好，見下） |

**主角**（`assets/kit/sprites.js`）

- 現在只有一種畫風：**程式畫的像素人物**（修修 2026-11-17 在 RPG 段落選的）。角色 `shosho`（像素版修修，
  黑短髮、黑 T 胸口橘牌；換色版本 `old`＝頭髮變灰）；道具圖示 `coin` `star` `book` `dumbbell` `heart`
  `cart` `bowl` `plane` `house` `briefcase` `question`。用字串一格一格畫，不用外部素材，顏色只有品牌色＋膚色。
- 動作：`EXK_SPRITES.hero(ctx, opts)` 走進來、原地走；`pop(icon, at)` 頭上冒出道具＋「+」、`hop(at)` 小跳、
  `jumpTo(at, left, top)` 跳到另一個位置、`variant(name, at)` 換色版本。排完呼叫 `walk()`。
- **主角身分固定、兩種畫風**（修修 2026-11-17 選 B）：主角固定是「修修」，畫風依情境二選一——
  - **像素**（上面）：遊戲、等級、闖關、數值成長這類比喻。
  - **品牌 logo 臉＋可動骨架**（`assets/kit/figure.js`）：其他情境，包括運動、姿勢、日常動作。
    頭是品牌 logo 臉原檔（`assets/brand/shosho_face.png`；`shosho_face_filled.png`＝原檔線條不動、底下墊白），不重畫；
    身體是程式畫的骨架（肩、肘、髖、膝可轉），姿勢 `stand` `armsUp` `armsOut` `squat` `star` `wave`，
    `pose(tl, name, at, dur)` 換姿勢、`jump(tl, at, h)` 跳。身體用**線條**款（`style: "line"`，修修 2026-11-17：
    「線條還蠻可愛的」）；剪影、剪紙兩款留在程式裡但不用，比較稿 `compositions/figure_study.html`。
  - 同一支動畫只用一種畫風。
  - 3D 場景、表情不在這裡做：那是第 15 類「Avatar 動畫」，用生成影片模型（修修 2026-11-17 選 C 混合）。
    本 skill 只做要精準對字幕／數字的 2D 解釋動畫。
- 要新的人物或道具：照同樣格式加，渲出來給修修看過再用。

## DP：規則

**品牌（積木已經做掉，填資料時不要破壞）**
- 顏色只有品牌冷灰 `#dddddb`、黑、白、橘 `#f57331`；字只有 Noto Sans TC Black。不加圓角、陰影、漸層。
- 橘色只有兩個用途：**正在講的那一個**、標題下的色塊。講過的回黑。所以畫面上同時亮橘的最多一個。
- 斜貼的牌一個畫面最多一張（品牌 ±2–6°），留給結論。

**清楚**
- 字是關鍵詞不是句子：一個標籤最多約 12 個全形字；數字 96px 以上、標籤 36px 以上。
- 一個畫面最多 3 組、每組最多 4 個項目；放不下就是 Director 要拆。
- 滿版：內容只放在 y 160–890（下面是字幕、左上右下是碎片）。疊加：右側側欄 x 1210–1850，
  人由畫面搬移讓到左 1/3（`youtube-reframe` `left`，跟側欄同一秒開始）。

**時間**
- 每個元素的出現時間＝那一拍的字幕開頭（秒數從這張開始算）。同一句裡講兩件事時，
  用字在句子裡的位置估（例：「那為某項消費多付300塊」的 300 在第 9 個字 → 這句長度的 8/12 處）——**這是估的**，
  渲完要對著聲音看；不準就改成那個字的實際秒數。
- 動作照積木（0.14–0.38 秒、落地回彈、退場更快），不加淡入淡出、鏡頭晃動、視差。
  **例外：漫畫**——分鏡表標「強調」的那一拍可以震動，見下面「漫畫（多格）」（修修 2026-11-20 同意）。

## 漫畫（多格）

人偶演一段情境、用好幾格分鏡講時用。範例：`compositions/comic_neat_office.html`（分鏡表 `storyboards/neat-office.md`）。
頁面骨架用 `assets/kit/comic.js`（格子、背景、運鏡、旁白框、大字、圖層、放人偶、收尾）——每支只寫「格子位置＋量出來的位置＋每格動作＋強調」，
不要再從頭手寫版面（`explore_office_*.html` 是當初 A／B／C 比較的實驗頁，不是範本）。
完整走過的例子：《財富階梯》咖啡段（`comic_coffee_p1/p2.html`、`storyboards/wealth-coffee.md`，2026-11-20～21，修修：「這個成果算還不錯」）、
高收入段（`comic_income_p1/p2.html`、`storyboards/wealth-income.md`，2026-11-21；**分鏡表照這份的格式寫**，五欄鏡位＋自己加的演出＋新鏡位參考）。

0. **先講清楚目的，再挑段落。** 動手前一句話說清楚這次畫漫畫要達成什麼——2026-11-20 一度在畫 NEAT 全篇，
   修修問「目的是什麼」才發現走偏（目的是驗證畫法，不是把某篇畫完）。
   - **字句和時間從哪裡拿**：一律以**成品影片同名的 .srt** 為準（不是流程中途的 transcript）。
     成品影片和 .srt 的路徑寫在分鏡表開頭。找不到成品 .srt 就停下來問修修，不要拿其他版本的字幕湊。
   - **挑段落的條件**：有具體的人在做的動作（不是純觀念）、有數字或東西可以變成畫面、有轉折（例：「但我還是只會買全家」）、
     長度約 20–40 秒（2 頁、9 格上下）。
   - **人偶只演修修**（或「你」——讓觀眾代入的一般人）。故事裡的別人（來賓、家人、老師）人偶不能演；
     需要別人出場的段落、訪談片段（來賓第一人稱在講）**先不挑**，等另外做其他角色的人偶（男女老幼）——修修 2026-11-22。
   - **先看成品那段現在是什麼畫面**：逐 2–3 秒截整段（只截 1 張會看錯——2026-11-21 第一次回報高收入段「大多是講話鏡頭」，
     逐段截圖後發現大半已經是 stock）。指令（`-ss` 放在 `-i` 前面才會快速跳到那裡；每張間隔 2.5 秒，第 i 張＝開始秒數＋2.5×i）：
     `ffmpeg -ss <開始秒> -t <長度> -i <成品.mp4> -vf "fps=0.4,scale=480:-1,tile=4x4" -frames:v 1 <對照表.jpg>`
   - 截圖裡分三類標出來：**講話鏡頭／已有 B-roll／已有解說圖卡**（概念 title、側欄條列、引用卡等別的分類已經交件的成果）。
     已有解說圖卡的時間**預設避開**；真的要蓋掉，就在候選寫明「會蓋掉哪一張」。
   - **候選怎麼給**：列 2–3 個，每個寫字幕句號、成品時間範圍、長度、符合哪幾條條件、成品那段目前的畫面（三類）、
     會用到哪些「沒試過」的鏡位。修修點頭才寫分鏡表。
   - **畫面不出現真實品牌**：字幕提到品牌（電腦、車、App、商店）時，畫成沒有商標、沒有名字的同類東西；
     生圖 prompt、道具、大字都一樣。
   - 跟已經畫過的段落相鄰時，沿用同一個世界（同一隻人偶、同一個場景圖、同樣的道具），兩段接起來才像同一支。
1. **先寫分鏡表，給修修看過才畫。** 每格寫：位置／大小、**鏡位五欄（景別／取景／角度／構圖／運鏡，名稱照
   [`shot-list.md`](shot-list.md)）**、跟上一格的跳法（名稱照 `shot-list.md`「跳法」；範例分鏡表沒有這欄，自己加一欄）、
   人偶（朝向、動作、表情）、文字（旁白框／泡泡／大字）、動作、強調、音效（照第 5 點的動作類型表填）、時間。
   分鏡表放 `storyboards/<段名>.md`。自檢：
   - 相鄰兩格景別不同；每頁至少一個物件插入格；`shot-list.md` 最後的自檢（角度、置中、插入要塞滿、新地點、字幕區）。
   - 不是每格都要有人偶——主觀鏡頭、插入格人不入鏡（修修 2026-11-21）。
   - 用到「沒試過」的鏡位：照 `shot-list.md`「新鏡位先找參考」先抽電影實例、畫完並排比。
     憑印象畫過肩鏡頭，2026-11-21 咖啡段第 1 格改了四版才對。
   - 稿上的數字變成畫面裡的東西；稿上的動詞用動作演出來；人往哪走臉朝哪（橫走用側面）。
   - 台詞、數字只能出自稿，不自己編。
   - **快速蒙太奇例外**：一格只有 1–3 秒、連續換好幾個地點（例：買精品 → 吃大餐 → 搭飛機）時，沒有時間每個地點先給建立鏡頭。
     做法：用只有物件的插入格（不需要交代地點），或用一個畫面元素交代地點（窗外的雲＝在飛機上）。分鏡表自檢裡寫明是例外。
   - **稿上沒有、你自己加的演出**（比喻、稿外的動作）在分鏡表另列一節「我自己加的演出」，給修修同意。
   - **人在用的東西，能看的那一面朝向用的人**：書頁、手機螢幕、電腦螢幕、文件朝向他自己，不是朝向觀眾——
     朝觀眾就變成「拿給別人看」，不是「自己在看」（2026-11-22 冷測「看書」格把書頁攤向鏡頭，修修：「這是書攤出來給別人看」）。
     要觀眾看到內容，換鏡位（過肩、主觀），不要把東西轉過來。檢查方法：把人偶換成真人想一次，這個動作自然嗎？
   - **最後一拍停 2 秒以上**（跟解說動畫同一條）。但時間跟講話對齊優先：往後延會蓋到下一張圖卡或下一段時不延，
     在分鏡表自檢寫明為什麼沒停滿 2 秒。
2. **場景**：每格一張不含人的背景（`tools/gen_panel.py`），鏡頭（景別、角度、要留空給人偶的位置）寫在每格的 prompt。
   - **不用生的格子**：物件插入格、特寫用素色底（cream）就好；同一個場景換景別，沿用已經生的圖放大或打模糊；
     沿用別段的圖要寫來源（例：高收入段格 6 沿用咖啡段 `assets/coffee/a3_high.png`）。
   - **畫風參考**固定用 `assets/explore/b/b1_hi.png`（`FIDELITY=low`，只借畫風）——咖啡段、高收入段、冷測都是這張。要換畫風先問修修。
   - **prompt 固定開頭**照抄 `storyboards/prompts/income/c1_tower.txt` 開頭到「no panel border.」那段（只借畫風、不准畫人、
     不准有字和商標），後面接「Scene: …」寫這格。沒寫這段，模型會畫出人或字。
   - prompt 檔放 `storyboards/prompts/<段名>/<格>.txt`，圖放 `assets/<段名>/`（費用自動記在那裡的 `_cost_log.jsonl`）。
   - 不要在 prompt 裡限制顏色和材質——第一版就是這樣變得很陽春。
   - 生圖不一定照 prompt 的方向（2026-11-21 格 10 寫「石階從左下往右上斜」，生出來是正對鏡頭往上延伸）。
     那格要傳達的事還做得到 → 改分鏡表配合背景（構圖、人偶動線），改的地方寫回分鏡表、交件時跟修修說；
     做不到 → 改 prompt 重生。
3. **人偶**一律用 `assets/kit/figure.js`（不讓生圖模型畫人：會走樣、也不會動）。特寫＝同一隻人偶放大對準部位
   （`lineWidth`＋`aim`），規則見 `assets/character/README.md`。
   人偶手臂比頭寬還短：只拍手的插入格要用小而方的格子（≤500px 寬）、手斜伸進畫面；寬格放大對準手，頭和身體一定會入鏡
   ——寬的物件插入格就讓人不入鏡，只拍東西動（2026-11-20 咖啡段撲滿格）。
   蓋在錄影上的漫畫**不放旁白框**（字幕已經有），時間照成品影片的字幕排，每格在那句開口時切進來。
   - **表情只有正面**：分鏡表要寫表情（笑、驚訝），那格人偶就要正面；側面、背面的頭沒有表情圖。
   - **人偶大小要每格重算**：同一張背景放進不同大小的格子，背景縮放（`C[k].s`）不同。先照比例換算當起點
     （新 scale ＝ 舊 scale × 新 s ÷ 舊 s），再看截圖：格子小時照比例算出來會太小，人在畫面上全身至少約 120px 才看得清楚
     （a3_high.png：咖啡段 1120 寬格 0.2；高收入段 632 寬格照比例是 0.13，看不清楚，用 0.22）。
   - 遠近縮放、跳躍壓扁、手上道具的分層規則見 `assets/character/README.md`。
   - **橘色**：程式畫上去的道具和大字，每格最多一個橘色＝那格的重點，其他用黑、白、灰（DP 品牌規則「橘色只給正在講的那一個」
     套到漫畫，修修 2026-11-22）。生出來的背景圖本來就是暖色調，不算。咖啡段、高收入段是這條之前做的，還沒照這條改色。
4. **動態**用 `assets/kit/fx.js`：角色寫在劇情時間軸 `act`、由 `drive` 推進（一拍二＋頓格），鏡頭／字卡／特效寫在主時間軸。
   - 每格有三層（`comic.js` 開頭註解）：整格轉角度、整格推近、震動動 stage（`cell[k]`，人偶、`P.svg` 圖層、大字都在這層）；
     scene（`C[k].scene`）只裝背景圖，背景放大動它。**同一拍又要推近又要震**（兩個都動 x／y，會打架）：
     把要震的內容搬進 scene（`C[k].scene.append(svg)`）、震 scene、推近照樣動 stage。
     沒有背景圖的格子 scene 是空的，直接震 scene 畫面上看不到——2026-11-22 冷測發現高收入段格 5 的震動一直沒震到，已改。
   - 頓格會讓**之後所有角色動作**在真實時間晚停格秒數，不只音效：照字幕排的 act 事件用
     `A(t) = t > 頓格點 ? t - 停格 : t` 預先扣掉（2026-11-21 高收入段頁 2）。
   - 強調分兩級，只用在分鏡表標了的那一拍；每頁最多一個「強」、兩個「中」：
     - **強**：撞到的那一格頓格 0.1–0.3 秒＋白閃（≤0.6）＋震動＋集中線＋衝擊環／撞擊線＋字彈出（後面墊衝擊星）。
     - **中**：震動一下（幅度 ≤8px）或速度線／動作線。
   - 人偶跳躍：預備（蹲）→ 拉長 → 落地壓扁（`squashJump`）。不加殘影（修修 2026-11-20 看過決定不要）。
   - 渲染器逐格 seek，**不能用 GSAP 的 onUpdate／call**（seek 時不會觸發），fx.js 都已經是逐格 set 或屬性補間。
5. **音效**：偏好電玩／卡通音效（修修 2026-11-20）。**音效跟著「動作類型」走，不是每支漫畫重挑**——
   分鏡表的每一個動作先歸到下表的一類，直接用那一類的音效，不再問修修：

   | 動作類型 | 音效（`sfx-dictionary.yaml`） |
   |---|---|
   | 走路、跑 | Cartoon Run |
   | 跳 | MARIO JUMP |
   | 小而快的重複動作（抖腳、敲手指、坐立不安） | FAST TIP TOES |
   | 轉（轉筆、轉身、轉圈） | CARTOON SPIN |
   | 數值上升、集氣 | 瑪利歐 Powerup |
   | 投硬幣、存錢 | 瑪利歐 Coin |
   | 衝擊（分鏡表標「強」那一拍） | 瑪利歐 Kick |

   - **哪些動作要配音效**：人偶的動作、分鏡表標「強調」的那一拍、物件的動作但**那個動作就是這格的重點**（例：鬧鐘響＝「五點起床」那格）。
     其他物件的動作（翻頁、東西放下）音效欄寫「—」不配。
   - 要配、但歸不進任何一類的動作才找新音效：挑 3 個候選、剪成同一段畫面的對照影片給修修聽，他選定後把那一類加進字典和這張表。
     以後同類動作就不用再問。
   - 字典記了落選的候選，同一類動作別再推薦。
   - 檔案從 `F:\Project Files\Assets\SFX` 複製進 `assets/sfx/`，在頁面 HTML 直接寫 `<audio data-start data-duration data-track-index data-volume>`
     ——**渲染器只讀靜態 HTML**，用 JS 加的 `<audio>` 不會混進影片。
   - 量每個檔開頭的空白（`silencedetect`），用 `data-media-start` 跳過，聲音才會跟動作在同一格；渲完再用 `silencedetect` 對一次時間。
   - 秒數是真實時間：頓格之後的事件要加上停格秒數。
   - `data-duration` 切在音效真的結束之後。有些音效尾巴不是真的靜音（`mario_kick.wav` 撞擊後有約 -25dB 的尾巴），
     切在尾巴中間會留一個台階，量時間時多一個點、也可能聽得到一聲小爆音——渲完戴耳機聽那一下。
6. **渲染**：影格率跟**成品影片**一樣。新影片 29.97（2026-11-22 起拍攝格式統一 XAVC S 4K 30p 140M 4:2:2 10bit）；
   舊影片先用 `ffprobe -v error -select_streams v:0 -show_entries stream=r_frame_rate -of csv=p=0 <成品.mp4>` 看成品是多少
   （《財富階梯》是 `30000/1001`；《不平等優勢》是 23.976＝`24000/1001`）。
   頁面 `EXK_COMIC.page(root, { …, fps: 24000 / 1001 })` 讓一拍二照同一個影格率走，渲染和預覽也給同一個值：
   ```bash
   cd video/compositions/explainer
   npx --yes hyperframes@0.7.72 render . -c compositions/<頁>.html -o <頁>.mp4 \
     --fps 30000/1001 -q standard --quiet --no-browser-gpu
   ```
   漫畫頁出 **mp4**（預覽工具吃 mp4），不用 `--format mov`、不用 `--variables-file`（那是型態模板用的）。
7. **驗證（每次改完都做，不只看 CI／不只看一張截圖）**——工具都在 `tools/`：
   - **逐格截圖**：`python -I tools/comic_shots.py compositions/<頁>.html <out.png> 秒數…`。
     每個動作的前、中、後都截（滑、點頭、跳、轉身、切下一格），看有沒有出格、被擋、看不懂、字寫到錯的面上；
     每格再問一次：**換成真人演，這個動作合理嗎**（書朝誰、手機朝誰、眼睛看哪裡）。
   - **跟參考並排比**：新鏡位照 `shot-list.md`「新鏡位先找參考」，逐條對寫下的畫面特徵。
   - **量音效時間點**：渲完 `python -I tools/sfx_onsets.py <頁>.mp4`，每個音效跟動作差不到一格。
     對不上任何動作的點，先查是不是片尾或某個音效的切點（工具開頭註解）。
   - **預覽影片**：`python -I tools/comic_preview.py --video <成品.mp4> --srt <成品.srt> --start <秒> --fps <成品影格率> --out <預覽.mp4> p1.mp4:<長> p2.mp4:<長>`
     ——蓋在成品原聲＋字幕上，跟上片後一樣，才看得出字幕有沒有壓到重點。交給修修的是這支，不是單頁。
8. **修修看預覽給回饋時**：不要只改他講的那一點就交。先逐格截圖找出「為什麼不對」（例：手機不自然＝螢幕朝觀眾、
   手被擋住、頭沒在看），一條一條列給他；畫不出來的鏡位找真實照片／電影畫面並排比，人偶做不到就換鏡位
   （過肩 → 主觀鏡頭），不要硬拼。最後把學到的寫回 `shot-list.md`（鏡位狀態）和這一節。

## 做法

1. 把解說需求換成內容 JSON（每個模板開頭的 `spec` 預設值就是範例）。秒數從字幕算，數字從稿抄或程式算。
2. 渲：
   ```bash
   cd video/compositions/explainer
   npx --yes hyperframes@0.7.72 render . -c compositions/<型態>.html -o <out>.mov --format mov \
     --fps 30000/1001 -q standard --quiet --no-browser-gpu --variables-file <spec.json>
   ```
3. **疊回錄影、帶聲音看**：初剪時間軸的那一段（跨剪點照剪）＋疊加版套 `left` 搬移＋疊上動畫。只看截圖抓不到對嘴。
4. 驗收：
   - 每一拍截一張圖：講到的那個是不是橘的、有沒有東西提早出現。
   - 用瀏覽器量版面：內容有沒有超出安全框（`getBoundingClientRect`；直接開模板檔就會用預設值畫）。
   - 畫面上每個數字對回稿；算出來的數字附算式。
   - 最後一拍停留 ≥ 2 秒。

交件格式同其他分類（`<episode>/visuals/<row_id>.mov`＋收據，`agents/brook/youtube_video/visuals/delivery.py`）——
**還沒接**：`explainer.py`（規劃表 → 內容 JSON → 交件）等型態定版再寫。
