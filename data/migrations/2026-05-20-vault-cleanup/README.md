## Manifest schema

`manifest.json` follows the schema from ADR-028 §3 Phase B "Pre-migration" spec:

```jsonc
{
  "schema_version": 1,
  "generated_at": "2026-05-20",
  "vault_root": "E:\\Shosho LifeOS",
  "repo_root": "E:\\nakama",
  "sub_op_counts": { "<sub-op-name>": <count>, ... },
  "total_ops": 103,
  "ops": [
    {
      "sub_op": "<sub-op-name>",
      "old_path": "<relative-to-vault-root or REPO:relative-to-repo>",
      "new_path": "<same>",
      "size": <bytes>,
      "sha256": "<hex>"
    },
    ...
  ]
}
```

`REPO:` prefix on `new_path` indicates a vault→repo cross-filesystem move
(per ADR-028 §4 durability split: Franky reports + dev artifacts land in repo,
not vault).

## Known residual drift

### `kb-attachments-flatten` — VPS deploy lag

`KB/Attachments/pubmed/` contains files written 2026-05-22 and 2026-05-23 by
the daily PubMed digest cron (Robin, runs 05:32 Asia/Taipei). The code in
`main` writes flat (`agents/robin/pubmed_digest.py:208-212`) per #656, so the
fact that new files land in the `pubmed/` bucket means the VPS Robin daemon
has not picked up the post-#656 deploy as of 2026-05-23.

**Resolution path** (out of scope for this archive, tracked separately):

1. Pull latest `main` to VPS + restart Robin
2. Verify next PubMed digest cron writes flat
3. Run `flatten_attachments.py` against `pubmed/` residual (use the existing
   script with `--scan-only` first, then commit)
4. Commit the resulting `2026-05-XX-pubmed-residual-flatten.json` manifest
   beside this archive

## Operational notes

- All deletes used PowerShell `Microsoft.VisualBasic.FileIO.FileSystem::DeleteDirectory`
  with `SendToRecycleBin` per ADR-028 §8 + project CLAUDE.md rules — no permanent
  removal. Files are recoverable from recycle bin if needed.
- Cross-filesystem moves (vault → repo) used `shutil.copy2` + recycle-bin delete
  of the source; the manifest's `sha256` allows re-verification at any time by
  hashing the destination.
- Rollback: each manifest entry has bidirectional `old_path` / `new_path` +
  `sha256`. A reverse script reading the manifest can restore prior state if
  needed.
