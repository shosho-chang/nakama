## 卡點

### 1. Reader inbox listing 連結沒 url-encode → 檔名含 `&` 開不了
- **重現**：Inbox/kb/ 內檔名含 `&`（範例 `American College of Sports Medicine Position Stand....  Medicine & Science in Sports & Exercise.md`），index 頁點「閱讀」→ 404 `找不到檔案：American College of Sports Medicine Position Stand....  Medicine `（被 `&` 切掉後段）
- **根因**：`thousand_sunny/templates/robin/index.html:88` `<a href="/read?file={{ file.name }}">` 沒做 urlencode；`&` 被當 query separator
- **臨時修**：`fix/reader-url-encode-filename` branch 加 `| urlencode` filter（QA 中暫不 commit，等其他 follow-up 一起處理）
- **延伸**：同檔 `routers/robin.py:338` (`/scrape-translate` redirect)、`:376`、`:439`（PubMed redirect）三處同 bug，但 :338 在 Slice 1 #352 工作範圍 — 等 Slice 1 merge 後一次開 PR 處理 4 處

### 2. Reader 沒 undo / delete UI — 標錯只能改檔或 DevTools console
- **重現**：Ctrl+B 標 highlight 或 Ctrl+Shift+C 加 annotation 後，沒任何 UI 路徑可取消；Ctrl+Z 不 work（annotationsData 是 append-only push）
- **根因**：`thousand_sunny/templates/robin/reader.html` 只有 add 沒有 remove；annotation 上沒 hover ✕、highlight 沒 toggle off、modal 沒 history undo
- **當下 workaround**：直接編 `KB/Annotations/<slug>.md` 刪條目 → reload reader；或 DevTools `annotationsData = annotationsData.filter(...); saveAndRender()`
- **建議補**：
  - annotation callout hover 出現 ✕ 按鈕直接刪
  - 同段文字再次 Ctrl+B toggle off highlight
  - Ctrl+Z 接 history stack（最近 N 條 add/edit/delete 可還原）
- **影響**：手跑時標錯動作摩擦大 — 心智成本「不能反悔」會讓修修標得保守

### 3. PubMed 雙語翻譯流程從未實測 + frontmatter 連結 bug
- **背景**：PubMed digest 抓的 abstract 純英文不翻譯；OA fulltext 翻譯走 `/pubmed-to-reader?pmid=...` (`thousand_sunny/routers/robin.py:472`)，產出 `KB/Wiki/Sources/pubmed-{pmid}-bilingual.md`（frontmatter `bilingual: true`，reader 才認雙語切換）
- **驗證結果**：`KB/Wiki/Sources/` 內 0 個 `*-bilingual.md` 檔 — endpoint 上線後從未被使用過
- **連結 drift**：digest 寫的 source page（如 `pubmed-42022829.md` line 46）frontmatter 連結 `http://localhost:8000/robin/pubmed-to-reader?pmid=...` — 多了 `/robin/` prefix，real mount 是 `/pubmed-to-reader`，**點下去 404**
- **建議**：Slice 3（issue #354 翻譯按鈕 + 雙語 reader B2-B flow）工作範圍涵蓋此區，順便修 frontmatter 連結 + 跑一次 OA fulltext 雙語驗收
- **影響**：QA Phase 1.2 雙語段落 gate 跳過

### 7. **【P0】sync LLM systematic invalid JSON — Phase 4/5 跑不下去**
- **重現**：3 次 sync 觀察
  - 第 1 次（creatine 首次） — 綠「已同步 3 個概念 ✓」 ✅
  - 第 2 次（creatine idempotency 不改 annotation 重按）— 「無匹配概念」、`merger LLM returned invalid JSON`
  - 第 3 次（cardio cross-source 標新 annotation）— 「無匹配概念」、`merger LLM returned invalid JSON`、**concept page 0 mutation**
- **systematic 訊號**：連續 2 次 invalid JSON 不是偶發；2/3 失敗率
- **三個層次的問題**：
  1. **LLM 輸出不穩** — Opus 4.7 是 reasoning model，對「raw text→必須 valid JSON」契約不穩；prompt 帶的 concept slugs 累積一兩百個 + annotations 內容後 LLM 容易出格式歪掉
  2. **silent swallow** — `agents/robin/annotation_merger.py:104-112` 把 JSON parse error catch 成空 dict 回去，UI 變「無匹配概念」誤導訊息（看不出 LLM 真壞掉 vs 真無匹配）
  3. **沒 short-circuit** — 第二次 sync (idempotency) 不該 call LLM；`unsynced_count == 0` 應直接 return cached state
- **建議補（按優先序）**：
  - **P0 修 LLM 契約**：改用 Anthropic structured output（tool_use forced JSON）或加 JSON repair retry layer；或退到 Sonnet（reasoning model 不適合嚴格 JSON 出）
  - **P1 surface error**：UI 區分「LLM 回應格式錯誤，請重試」(error) vs 「無匹配概念」(empty result)；merger 回 typed result
  - **P2 idempotency short-circuit**：merger 入口檢 `unsynced_count == 0` → 不 call LLM，直接 return last sync result
- **QA 影響**：**Phase 4 cross-source aggregate + Phase 5 edit/delete 全 block** — 兩個 phase 都靠 sync 驗收，sync 連續失敗則無法驗 per-source boundary 隔離 / full-replace 語意
- **歸類**：PRD #337 真實 P0 bug，是這次 QA 唯一硬 block；下個 PR 必修

### 6. Opus 4.7 是 reasoning model 但 LLM call 仍傳 `temperature` → API 400
- **重現**：reader 按「同步到 KB」→ syncIndicator 紅色「同步失敗」；server log 噴 `anthropic.BadRequestError: 400 - 'temperature' is deprecated for this model.`
- **根因**：`agents/robin/annotation_merger.py:102` `ask(..., model="claude-opus-4-7", temperature=0.2)`；Anthropic 對 reasoning model（Opus 4.7）已 deprecate `temperature`
- **同 bug 第 2 處**：`shared/kb_writer.py:132` 同 pattern — textbook ingest / Concept upsert 4-action dispatcher 全 production 路徑會炸；目前 QA 主軸不碰，但下次跑 textbook ingest 必爆
- **臨時修**：`annotation_merger.py:102` 直接刪 `temperature=0.2` 行（已動，未 commit）— 解 QA 卡點
- **建議補**：
  - `shared/anthropic_client.py` 對 reasoning model（model 名含 `opus-4-7` / 未來新 reasoning 系列）自動 strip `temperature` — 一處解全 codebase
  - 或補 `feedback_*` memory：Opus 4.7 不接 temperature，所有 caller 不可傳；CI grep 護欄
- **影響**：所有經 LLM 的 sync / merge / upsert 路徑全炸；Phase 3-5 sync 主軸 block

### 5. Annotation callout reload 後位置跑掉（multi-occurrence 抓 first match）
- **重現**：Ctrl+Shift+C 標 annotation 後第一次顯示位置正確；reload reader → callout 跑到別段（如 abstract / 摘要 / 結論裡相同短語的位置）
- **根因**：`thousand_sunny/templates/robin/reader.html:456-462` `findInStr` 用 `regex.exec(src)` 只回第一個 match；annotation file（`KB/Annotations/<slug>.md`）只存 ref text 字串，沒存 occurrence index / paragraph anchor / surrounding context hash → reload 時 `buildAnnotatedMd` 純 text match 抓文檔第一個出現位置
- **第一次顯示為什麼對**：標的當下 DOM selection 是物理位置；保存後 ref 失去這個 anchor，下次 render 只剩 text fuzzy match
- **建議補**：annotation item schema 加 `occurrence_index`（這是該 text 在文檔中第幾次出現）或 `context_before` / `context_after`（前後 50 char 字串），render 時 nth-match 或 context-anchor 找位置
- **影響**：annotation 在重複用詞的長文（雙語 / 學術論文 abstract+conclusion 重複關鍵句）會錯位；Phase 4 cross-source aggregate 不影響（sync 走 ref 文字 + concept matching，不靠 reader 渲染位置）
- **歸類**：ADR-017 位置 anchor 設計缺口

### 4. 中文 EPUB 一般書籍 ingest 流程不存在（Line 2 critical path 真 blocker）
- **重現**：`agents/robin/ingest.py:98-106` 對非 PDF 檔走 `read_text(raw_path)`，EPUB 是 zip 包 XHTML 拿到亂碼 → LLM 摘要垮；`/start` flow 對 EPUB 直接 broken
- **更深的 gap**：即使 EPUB 能讀，現在 pipeline 是 「LLM 一次性摘要 → wiki」，跟修修要的「**讀完 + annotation + 心得 → wiki**」流程形狀不同
- **textbook-ingest skill** 走 chapter-by-chapter 切片並行 ingest，是教科書專用流程（`KB/Wiki/Sources/{book}-ch1.md` 等），不出整本 md，且設計是「一邊 ingest 一邊抽 concept stub」，不等修修讀完
- **修修要的形狀**：
  1. EPUB → 完整 markdown 轉檔器（保留章節結構、一字不漏）
  2. Reader 邊讀邊 annotation（PR #342/#343 已 ship）
  3. 「我讀完了 → trigger ingest」按鈕：用 annotation 為 seed 抽 concept + 修修手寫心得入 wiki，**跳過 LLM 一次性摘要**
- **歸類**：Stage 1 ingest 範疇但跟 PRD #351 的 URL ingest unify 是兩碼事；下一輪獨立 PRD「一般書籍 ingest」處理
- **影響**：QA Phase 1.3 + 1.4 EPUB ingest gate 全跳過
