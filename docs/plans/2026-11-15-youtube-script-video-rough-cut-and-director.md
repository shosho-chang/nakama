## 1. 跨階段的共同規則

### 1.1 時間軸版本制

修修：「我如果修正過timeline，那程式知道了這個修正，就把它記錄成一個新的版本，然後它可以自己再往這個基礎去做它的版本。這個新的版本如果我又做新的修改，那又是另外一個新的版本，一直到我說確定沒問題才定版」；「我不想要做手動拖素材檔這件事情」。

- 程式每次動 Resolve 之前，先**讀回目前的時間軸**存成最新版本；程式的修改一律以最新版本為基礎，**新鋪一條**成為下一版。
- Resolve 程式介面沒有「插入並把後面往後推」（`DaVinciResolveScript.pyi` 只有 `AppendToTimeline` 與 `DeleteClips(..., rippleDelete)`），所以章節卡、頻道動畫、montage 這類插入，一律靠整條重鋪完成。
- 修修改、程式改交替進行，直到修修說「定版」。沒有手動拖素材的步驟。
- 修修在 DaVinci 的最後細修以他的版本為準。修修：「當DP素材全部確定之後，我就會在 DaVinci Resolve 上面做最後的修正。這個是比較細部的，當然是以我修正之後的為主。」
- （推論）每個畫面綁在「它蓋住的那幾句字幕」上，不綁秒數。修修刪掉那句，該畫面拿掉並在 Bridge 回報。

### 1.2 舊版時間軸收進子 bin

修修：「我只想在工作區上面看到新的 timeline。至於舊的 timeline 的檔案要放在 master 底下創造一個新的 bin 出來把舊的放進去，要不然我的 master folder 會變得很雜亂。」

- 新版設為目前時間軸（`SetCurrentTimeline`）。
- 上一版移進 Master 底下的子 bin **「舊版時間軸」**（修修確認名稱）。介面：`MediaPool.AddSubFolder`、`Timeline.GetMediaPoolItem()`、`MediaPool.MoveClips`——型別檔有，未實機驗證。

### 1.3 字幕外觀

修修：「可以」（沿用現有樣式）。

- 用現有「Shosho YT」字幕樣式。Resolve 程式介面不能設字幕樣式，樣式靠 DRT 模板帶入（`resolve-project` skill「字幕樣式 preset」節）。
  - **YouTube 用 29.97 的模板 `E:\nakama\data\resolve\subtitle-template-2997.drt`**，不能用 podcast 的 `subtitle-template.drt`：DRT 自帶幀率、匯入後改不動，podcast 那份是 30 fps，YouTube 錄影是 29.97 drop-frame——混用時畫面每秒漂千分之一、字幕到片尾晚 1 秒（2026-11-16《財富階梯》流程測試實測）。
  - 29.97 模板做法：在 29.97 專案建空時間軸 → 放一句字幕 → Inspector 右上「⋯」→ Shosho YT → Load Preset → 刪掉那句 → `Timeline.Export(…, EXPORT_DRT)`。
  - 專案幀率只能在全新專案、還沒匯入東西時設（之後鎖住）；播放幀率（Playback frame rate）程式介面設不進去，新專案要在專案設定手動改成 29.97。
  - 程式：`agents/brook/youtube_video/timeline.py`（從初剪剪點建「v1 初剪」）。
- 每一版時間軸都**從模板建立**；字幕軌只換內容、不可刪除重建（樣式掛在軌上）。

### 1.4 稿的快照

修修：「可以，直接寫」。開始處理錄影時，把稿複製一份進這一集資料夾（記雜湊），整集都用這份副本；之後在 vault 改稿不影響這一集。

### 1.5 語意工作由當下的 agent 做

修修 2026-11-14：「把指定 codex 全部都拿掉，只交給當下的 agent」。校對判斷、Director、重排都由對話中的 agent（或它開的 subagent）做，不開背景程式、不走 API key。

## 2. 初剪 skill

修修：「可以，獨立成一個 skill，字幕要放上時間軸。」**skill 名稱未定。**

- **輸入**：原始錄影檔＋文字腳本。修修：「基本上錄影就只會有一個檔而已」。
- **輸出**：Resolve 上粗剪好的時間軸、Auphonic 處理過的聲音、字幕軌、校對後的 SRT（交給 Director）。

### 2.1 稿的格式

- 一段＝有空行隔開的一塊。修修：「一段就是我有空行的，叫做一段。」
- 不唸、不比對：標題行、`##`／`###` 小標題、`## Reference` 底下的內容。
- `## Outro`：標示正片結束（§3.5）。

### 2.2 錄影方式

- 聲音錄在影片裡，一次錄完。
- 講錯就拍手，從該段第一句重講。修修：「B，拍手觸發，用稿決定刪到段落開頭。」

### 2.4 錄影時的特殊狀況

修修：「可以，直接寫」。

- **同一段連錯多次**：每次拍手都把「段落開頭→拍手聲」整塊刪掉，只留最後一次完整唸完的版本。
- **唸錯但忘了拍手**：程式比對發現疑似重唸，但不剪，在報告列出時間點，修修在 DaVinci 補剪。
- **用詞相近的段落**（例：重點整理 vs〈到底該怎麼花錢？〉）：判斷「正在唸哪一段」時只在目前這段和後面找，不跳回前面章節。

### 2.5 字幕校對規則

修修：「你列的那四個例子都沒錯」、「我是傾向全部交給 agent 來判斷就好了」。

- 字幕以修修**實際講的**為主，稿只用來修辨識錯字與專有名詞。
- 辨識錯（「財富接替」→「財富階梯」）→ 用稿。
- 換說法（稿「今天」、講「這次」）→ 保留講的。
- 臨場加講整句 → 保留講的。
- 稿上有、沒講的句子 → 不出字幕。
- 語助詞：**稿上沒寫的一律拿掉，稿上寫了的保留**。修修：「可以」。
- 判斷者：預設 Sonnet。第一集同一份清單也給 Haiku 判，只把兩邊**意見不同**的地方列表給修修裁決（Memo 聽到的字／稿上的字／Sonnet 判斷／Haiku 判斷）。Haiku 與修修一致的比例和 Sonnet 相當 → 之後改用 Haiku；明顯較差 → 續用 Sonnet、不再對照。修修：「可以」。

### 2.6 字幕文字規則

修修：「可以」。沿用 podcast 字幕 house style（`memory/claude/feedback_subtitle_house_style.md`、`shared/subtitle_finalize.py`）：

- 書名加《》、術語與自創概念加「」，其他標點省略、停頓用半形空格。
- 依語意與詞的邊界斷句，不用字數硬切（14／22 軟硬上限）。
- 字幕之間不留空隙。

兩處例外：語助詞改用 §2.5 的規則；**數字照稿上的寫法**。

## 3. Director

### 3.1 輸入

修修：「Director 的輸入就是這兩個東西，沒錯。」

2. 稿的快照：`##`／`###` 當章節結構，`## Reference` 當出處參考。

### 3.2 排畫面的方式

- **單位**：Director 自己切「一個畫面想法」，可以跨好幾條字幕。修修選 C。
- **時間精度：整句字幕**。畫面從某句字幕開頭出現、到某句字幕結尾消失；第一版不做詞級時間。修修：「A 整句字幕」。時間不準的列，在 Bridge 重排或改時間。
- **一次規劃全部畫面**，交 Bridge 讓修修修正。修修：「我知道現在 Director 要一次 one shot 就把這些畫面全部編排好是辦不到的，所以我希望在這裡加一個 human-in-the-loop。」
- **品質標竿**：修修：「這個導演必須要對畫面相當敏銳，而且對 YouTube 的影片畫面經驗豐富，我很希望他能夠效法 Vox」。但不在第一版一次對標：「先不要拆 Vox 好了，我們之後依照他做得好的地方再慢慢加進去吧。」

### 3.3 畫面分類清單

- **唯一來源**：repo 內一份結構化清單檔（YAML），記每類的名稱、什麼時候用、DP 怎麼做、規劃表必填欄位、**目前做得出來嗎**。Director、DP、Bridge、檢查程式都讀它。修修選 B。
- **全部開放**：Director 可以選任何一類；做不出來的類別在 Bridge 標「待製作」。修修：「A，DP這 16 種功能，我每一個都會跟你合作討論一個 skill 出來……我希望這個DP可以動用到的 skill 是會越來越擴增的，以後可能不只有這 16 個，像是情境動畫這個，我一定會把它做好」。
- **擴增方式**：新增一類＝清單加一筆＋做一個對應的 DP 子 skill。

### 3.5 開場、推廣段、片尾

**開場**。修修：「我頻道的動畫跟一個 Jingle 是加在我一開始的 Hook 跟頻道自介的中間，這個我會提供給你。頻道自我介紹前，就算都算是開場。」

- 頻道自介段＝稿上第一個以「嗨大家」開頭的段落。修修：「頻道自我介紹一定從『嗨大家』開始講，每次都會一樣」。找不到時不猜，Director 在規劃表標出、由修修在 Bridge 指定。

**課程推廣段**。修修：「可以」。

**片尾結語**：修修選 C，「結語交給 Director 判斷」。不沿用舊手冊的固定片尾 CTA，不預留 YouTube 結束畫面。

### 3.6 跳接處理

修修：「Punch in 是其中一個普遍的方法，而且在 punch in 的這個地方留的空白要小一點……我之前在做的時候，大概只有留 3 到 4 個 frame 左右……另外在 jump cut 一開始用滿版的 B-roll 或是滿版的 Hyperframe 動畫來處理，應該也是目前最常使用的。之後我錄影時可能會加上第二機，這時候 jump cut 就可以切到另外一個角度的鏡位」。

- 三種處理：
  1. **推近**：剪點前後空白只留約 3–4 frame（暫定）。
  2. **剪點一開始蓋滿版畫面**：B-roll 或 HyperFrames 動畫，最常用。
  3. **切第二機角度**：等加第二機後。
- Director 決定每個露出來的剪點用哪一種（被畫面蓋住的不處理），列進規劃表由修修核准。修修：「可以」。
- **校準**：修修在 DaVinci 手剪到順暢後，程式讀回時間軸時量出推近剪點實際留了幾個 frame，回報修修，用實測值取代暫定值。

### 3.6a 畫面搬移（2026-11-15 定版，skill `youtube-reframe`）

修修：「在螢幕上畫東西，以及變更影片 frame 的大小跟位置，這兩件事是分開的」。三種搬移都是 0.5 秒 ease-in-out、
眼睛高度不變，結束時同速退回：

| 種類 | 放大 | 臉最後在哪 |
|---|---|---|
| 原地推近 | 1.3 倍 | 原地 |
| 放大左移 | 1.4 倍 | 畫面寬度 1/3（書封在右時用） |
| 放大右移 | 1.4 倍 | 畫面寬度 2/3 |

做法是在 Resolve 片段上用 Fusion Transform 逐格打關鍵影格（Python Fusion API，寫完逐格讀回）。
這跟 §3.6 第 1 種「推近」不同：那是跳接剪點的硬切。原地推近什麼時候用、由誰觸發還沒定。

### 4.3 操作

- **新增畫面**：修修選 B，「空白段收合，展開再加畫面」。表照時間排序；兩個畫面之間自動插一列「空白段」（如「1:42–2:10，28 秒沒有畫面」），預設收合；展開後列出該段每條字幕，選一條或連續幾條 →「加畫面」。「給 DP 的指示」可留空由 Director 補寫。
- **直接修改**分類、版面、畫面描述、畫面上的字 → 改完即核准該列。
- **刪整列** → 併入前後空白段。
- **時間**只能從字幕重選起訖，不能直接打數字。
- **儲存**：修修選 A，自動儲存（離開欄位即存，列旁顯示「已儲存」）；每列「復原」回到 Director 原版。
- **表頭**：進度（已核准／待審／重排）、§3.7 的兩個密度數字（最長空白段可點擊跳過去）。

### 4.4 重排流程

1. 修修標「重排」並寫原因 → 在對話說「重排好了」。
2. 當下的 agent **只**重做標重排的列與待補指示的新增列；同時被修修改動的其他列以修修的版本為準。
3. 重做的列回到待審；全部核准才交 DP。
4. DP 開工前，把整集要下載的檔案（每份的檔名、來源、大小）**一次列給修修核准**，不逐份打斷；清單外的檔案再另外問。修修 2026-11-16：「先依照你的建議補上去吧，要到時候真的跑一次，才知道有哪些需要再修改。」

### 4.5 DP 做完之後

修修選 B：「反正做出來就全部上 Resolve，我快速瀏覽過一次，就可以判斷哪些要不要改。」修修：「我在 Resolve 看過，把要改的意見寫回 Bridge 不就好了嗎？」
