0. 一句話

三條路線閱讀時的劃線／註解，底層已經統一存進 KB/Annotations/{slug}.md（V3 schema，機器格式）。本規格新增的是「按下 ingest 後，從那份機器資料 render 出一份人也讀得懂、可被知識庫連結的 Literature Note」，三路共用一套 frontmatter、body 依證據形狀微調。

1. 為什麼要做（現況的問題）

核對 codebase 後的真實狀況：

已經統一的（好消息）：三條路線的劃線／註解全部寫進 KB/Annotations/{slug}.md，用同一個 V3 schema（shared/schemas/annotations.py）。三種 item：

  • HighlightV3 — 純劃線（body=劃線文字）
  • AnnotationV3 — 劃線＋你的短註（body=note）
  • ReflectionV3 — 章末／整體長心得（body=prose；此欄特地從 CommentV2 改名 reflection 對齊使用者詞彙）

差別只在填哪個錨點欄與 base：書＝cfi、文章／論文＝text_excerpt/ref、影片＝cfi 欄裝 t=<起>-<迄> 秒數＋speaker。

還沒統一的（要做的）：「人讀的那一份」目前散成四種方言：

來源 現有人讀產物 frontmatter type producer
書 Sources/Books/{id}/notes.md book_notes agents/robin/book_notes_writer.py
書 Sources/Books/{id}/digest.md book_digest agents/robin/book_digest_writer.py
文章（舊路徑） Sources/{slug}.md source agents/robin/ingest.py
文章／影片（promotion） Sources/{slug}/whole.md source_page shared/promotion_renderer.py

四種 frontmatter 互不相同、body 結構也不同——這就是「之前三條各自做」的後果。本規格把這層收斂成一個 type: literature。

真實樣本：《財富階梯》已讀完，KB/Annotations/財富階梯.md（56KB）內有 70 條 highlight ＋ 8 條 annotation（真實 note，如「這就是刻意練習的理論」「就是練等典技能樹啦!」）、0 條 reflection（所以它只有 digest.md、沒有 notes.md）。KB/Wiki/Concepts/ 為 0 檔。Permanent/、Fleeting/、MOCs/、Literature/ 皆不存在（greenfield）。

2. 已拍板的決定

# 決定 備註
D1 雙檔制 KB/Annotations/{slug}.md（機器 JSON，Reader 擁有、閱讀期間動態更新，不動）＋ KB/Literature/{slug}.md（人讀，ingest 當下 render 的快照）
D2 統一 frontmatter 見 §4。三路共用 type: literature
D3 body 依路線微調 見 §5。書按章＋CFI、文章平鋪＋段落錨、影片按時間軸＋講者
D4 digest 的撈卡功能升級為三路共用 把 book_digest 的「📚 KB 相關 ＋ 👍/👎 回饋 ＋ 開回 Reader 深連結」抽出來，變成 Literature Note 的共用 ## 🔗 KB 相關 段（不再書專屬）
D5 退役兩個舊 book writer book_notes_writer ＋ book_digest_writer 停用；notes.md/digest.md 退場（見 §6 migration）
D6 文章補位置錨 文章／論文目前只記劃線文字、無位置錨；這次補段落錨 ^p-N，讓文章劃線也能穩定被引回原文
D7 《財富階梯》當第一個 pilot 樣本 migration 時從它的 annotation store 重 render 出第一份 Literature Note

選雙檔的理由：Reader 存註解時會把整個 KB/Annotations/{slug}.md 重寫成「frontmatter + JSON 區塊」（shared/annotation_store.py:_serialize）。人讀 prose 塞同檔會被這個寫入路徑蓋掉、且逼改 Reader。雙檔讓機器檔零改動、人讀版是純下游 render，可隨時重畫不碰資料源。

3. 儲存位置與每來源的四個檔

統一後，每個來源最多有四個各司其職的檔（單一擁有者、單一目的）：

檔 角色 擁有者 動態？
KB/Raw/{類}/{slug}.md 或 EPUB 原文（不可變證據） 🤖 ingest 帶入，之後唯讀 否
KB/Annotations/{slug}.md 劃線／註解資料源（機器 JSON） 🤖 Reader 閱讀期間動態
KB/Literature/{slug}.md ← 本規格新增 人讀的文獻筆記（ingest 快照） 🤖 render，🧑 閱讀 ingest 當下凍結
KB/Wiki/Sources/{slug}.md AI 的來源摘要（它的話） 🤖 promotion ingest 後

Literature Note 與永久卡的關係留待下一份規格：永久卡 KB/Permanent/{概念}.md 是你從 Literature Note 提煉、用自己的話寫的（紅線：AI 不寫）。Literature Note 的 mined_concepts 欄回填你寫出的永久卡連結。

4. 統一 frontmatter（canonical）

---
type: literature                          # 統一名詞，取代 book_notes/book_digest/source 四方言
source_kind: book | article | paper | video
slug: 財富階梯
title: 財富階梯
author: "[[Entities/...]]"                # 向上溯源（ingest 自動建，若可辨識）
annotations: "[[Annotations/財富階梯]]"     # ← 雙檔連結：指回機器資料源
source_digest: "[[Wiki/Sources/...]]"     # 連到 AI 的來源摘要（若已 promote）
source_url:                               # article / video
status: capturing                         # capturing → digested → mined
mined_concepts: []                        # 你提煉成永久卡後 AI 回填 [[Permanent/...]]
anchor_type: cfi | excerpt | timestamp    # 證據錨點型別（per route）
book_version_hash:                        # 僅書：偵測改版斷錨
captured: 2026-05-25                      # 第一次劃線日
ingested: 2026-06-10                      # 按下 ingest 日
schema_version: 3                         # 對齊 annotation store
tags: []
---

兩個關鍵新欄（把 Literature Note 接進永久卡流程）：

  • status：capturing（還在讀／標）→ digested（ingest 完、AI 摘要寫好、本筆記 render 好）→ mined（你已從中提煉 ≥1 張永久卡）。
  • mined_concepts：你寫完永久卡後，AI 回填 [[Permanent/...]] 連結（記帳型，AI 可寫）。

frontmatter 先這樣；之後需要再加（例如 area: 對應健康/工作/專注四象限、reading_completed 旗標）。

6. 退役 notes.md / digest.md 的 migration（含 consumer 清單）

不是一刀刪——三個地方還在讀它們，得先接到新檔。但因 Brook 寫作 context 尚未正式使用，可直接改掉那幾處 read、不需保留舊行為。

現有 consumer（read）：

  • agents/brook/context_bridge.py:138-145 — Brook synthesize 讀 digest.md + notes.md
  • agents/robin/reading_context_package.py:17-19 — RCP 讀 digest.md→EvidenceItem、notes.md→同
  • agents/robin/kb_search.py:178 — kb_search 掃 notes.md

現有 producer（write，需改）：

  • agents/robin/annotation_merger.py — 目前把章末心得灌進 book_notes_writer；改流進 Literature Note

退役順序：

  1. 建統一 Literature Note writer（涵蓋 notes 章末心得 + digest 逐條 + 🔗 KB 相關）。
  2. consumer 改指向 KB/Literature/{slug}.md（Brook context_bridge、RCP、kb_search）。
  3. 改 annotation_merger：reflection 不再進 book_notes_writer。
  4. 停 book_notes_writer、book_digest_writer。
  5. 既讀書本（《財富階梯》《發現我的多重職涯組合》《讓你的思緒平靜下來安然入睡》）從 annotation store 重 render → KB/Literature/；舊 notes.md/digest.md 丟回收桶（PowerShell recycle bin，不用 rm）。
  6. 同 PR 更新 docs/VAULT-LAYOUT.md（登記 KB/Literature/、移除 notes/digest 列）。

不會丟失任何內容：你標的東西真相在 KB/Annotations/，migration 是拿同一份資料源重畫。

0. 一句話與第一性原理

按 Ingest = 凍結你讀的痕跡 → AI 做所有記帳與編纂 → 在紅線前停下 → 把「寫永久卡」這個會產生理解的動作交還給你。

貫穿全程的判準（摩擦篩選）：會產生新判斷的動作留給人（寫永久卡、定關係、選邊），純損耗的動作交給 AI（搬運、摘要、抽實體、撈相關、補記帳、標矛盾）。

3. Phase 1 — 凍結 + 產生 Literature Note 🤖（自動，純機械）

觸發：按 Ingest。動作：

  1. 凍結該來源的 annotation set（此後 ingest 流程以這份快照為準）。
  2. 從機器檔 render 人讀的 KB/Literature/{slug}.md（依 Literature Note 規格 v0.1）： - frontmatter：type: literature、source_kind、anchor_type、status: digested、annotations: [[Annotations/{slug}]]、mined_concepts: []、author、captured、ingested… - body：## 劃線與心得（依路線版型：書按章+CFI、文章+段落錨、影片+時間軸/講者）+ ## 🔗 KB 相關（見下）。
  3. 機器檔不動（雙檔分離，零蓋寫風險）。

## 🔗 KB 相關 的產生（吃社群的「兩段式連結探勘」）：對每條劃線/概念，先用 kb_search(FTS5) 撈候選 → 再讓 LLM 判斷「真概念關係 vs 表面相似」過濾（擋掉你實測 digest 那種「財富劃線撈到 wingate test」的雜訊）→ 列出相關的既有 Permanent/Concept 卡，每項配 👍/👎 + 開回 Reader 深連結。檢索排序把 Permanent 提到最前（你親手寫的優先，fork 2）。

真實接點：取代現有 book_digest_writer / book_notes_writer（退役見 Literature Note 規格 §6）；文章路線從 IngestPipeline 既有的 annotation 讀取改吐 Literature Note。

4. Phase 2 — LLM 編 Wiki 🤖（自動，Karpathy loop，順序鎖）

這一段就是 Karpathy 的 ingest → 整合 → lint，落到你的 codebase。核心精神：每個來源「整合進既有頁面」，不是只新增一頁（更新 entity、改寫摘要、標矛盾）。順序鎖：Sources → Entities → Concepts → Index/Log。

ⓐ Source digest → KB/Wiki/Sources/{slug}.md AI 讀 Literature Note + raw → 寫/更新「這個來源」的綜整摘要，每個事實宣稱附 citation ^錨點 回 raw/annotation（🚧 紅線②）。真實接點：shared/promotion_renderer.render_source_page / kb_writer.write_source_page。

ⓑ Entities → KB/Wiki/Entities/{name}.md 抽專有名詞（人/組織/產品）→ upsert（新建 or append「在此來源被提及」，不覆寫舊內容）→ 在 Source 頁連 [[Entities/...]]。Entities 是兩層映照的共用底料（你的 Permanent 與 AI 的 Concept 講同一人時都指向它）。

ⓒ Concepts → KB/Wiki/Concepts/{slug}.md LLM 寫/merge 它自己的概念理解（自由寫 + Opus diff-merge，維持平行權威層、不降級為候選——推翻 ADR-043 decision 3）。cite 回 sources/raw。 → 映照動作：若某 Concept 對到一張既有的人寫 Permanent/X，AI 加雙向連結並 defer（在 Concept 頁標「對應永久卡 [[Permanent/X]]，以人寫版為『修修怎麼想』的權威」）。AI 不改寫 Permanent。

ⓓ Index + Log - KB/index.md：更新/新增 Source、Concept、Entity 條目，並同步列出該主題的 Permanent 卡（一份 index 蓋住兩層，Q3 接點①）。 - KB/log.md：append 一筆 ## [YYYY-MM-DD] ingest | {標題}（grep 友善）。

inline lint：寫入時若與既有頁面矛盾，標記矛盾（不靜默覆蓋）。完整 lint（孤兒、過時、缺概念頁、CJK 錨點斷鏈、prompt-injection 健檢）走 Phase 6 後的排程，不卡 ingest。

5. Phase 3 — 提示 + 處理座艙 ⚙️（系統）

AI 自動工作做完，系統提示：「要不要趁熱寫永久筆記？」並開出處理座艙（pilot 期 = Obsidian 側欄 / CLI context；過 gate 才做完整 Bridge UI）。座艙一次顯示：

  • 你的 Literature Note（劃線 + 心得）；
  • AI 剛寫的 Concept 頁（它的理解，當參考、不一鍵採用）；
  • ## 🔗 KB 相關（LLM-judged 的相關既有卡）；
  • Nudge 清單（社群的「nudge not ghostwrite」）：
  • 「這幾條劃線/概念值得做成永久卡」；
  • 「可連到這些既有卡——支持 / 矛盾 / 延伸？」（給候選 typed edge，理由留你補）。
  • 兩個時機：趁熱（現在進 Phase 4）或 留到每週 review。

🚧 ingest 自動流程到此為止。AI 不再往下。

6. ═══ 🚧 紅線 🚧 ═══

以下 Phase 4 起，正文與關係由人寫。AI 路徑的 target resolver 永遠解析不到 KB/Permanent/；AI 唯一能碰永久卡的入口是只改記帳型 key 的 update_permanent_bookkeeping()。每筆寫入帶 author: human | agent_*。tripwire 測試斷言：promotion target 永不回 KB/Permanent/、永久卡正文寫入只來自 human 路徑。

7. Phase 4 — 寫永久筆記 🧑（人，趁熱 or 每週）

在座艙/Obsidian 裡，你看 Literature Note + AI Concept + 證據 + 建議連結 → 用自己的話寫 KB/Permanent/{概念}.md：

---
type: permanent
status: seedling            # seedling → budding → evergreen（成熟度晉級＝你的判斷，AI 不得改）
author: human
source_refs: ["[[Annotations/財富階梯]] ^cfi-..."]   # 記帳型，AI 可代補錨點
created: 2026-06-10
---
  • 正文：一卡一概念、用自己的話（原子規格）。
  • 採納連結並寫關係：> 支持 [[Permanent/...]] / > 矛盾 [[...]] / > 延伸 [[...]]——這個 typed edge + 理由就是「理解的痕跡」，是紅線、留人（也正好補上 Karpathy 原版「untyped edges」的缺口）。
  • 你看 AI 的 Concept 當參考，但不一鍵採用（🚧 紅線③）。

技術上是「authoring surface 寫磁碟」，但那算你的 authorship。pilot 期 surface = Obsidian；之後 = Bridge。

8. Phase 5 — 記帳善後 🤖（自動，你寫完後）

你存檔後，AI 做純記帳（全是記帳型，不碰正文/status）：

  1. 鏡像反向連結：你建了 Permanent/X，AI 在對應的 AI Concept 頁、Literature Note、被引的 Source 頁補上 backlink（Q3 接點②）。
  2. 回填 Literature Note：mined_concepts: [[Permanent/X]]，並把該 Literature 的 status → mined（Q3 接點④，Literature 是來源層的鉸鏈）。
  3. 回填永久卡記帳欄：source_refs 錨點、created/modified、aliases（跨語 卡片盒↔Zettelkasten）——經 update_permanent_bookkeeping()。
  4. 更新 KB/index.md：讓新永久卡出現在共用 index（Q3 接點①）。

9. Phase 6 — MOC / Home 🧑+🤖（擠壓點才做，非 ingest 觸發）

不由 ingest 觸發。當某主題的永久卡多到「找不到了」（mental squeeze point），你把它加進 KB/home.md，或某區擠爆抽成 KB/MOCs/{主題}.md。AI 維護骨架（撈相關卡、列清單、標孤兒），你定主題邊界與分組、寫關係。一張卡可掛多個 MOC。

11.5 互動與複利（Karpathy 複利引擎）

根本分工：覆蓋率 vs 意義

LLM ingest = 全文、無差別、巨細靡遺（覆蓋率）；人 = 選擇性、有感才記（意義）。兩種互補的理解，是 AI 能同時當秘書（圖書館員）+ 寫作教練的根據：

  • 秘書：它握著你只掃過的全文，所以你問「那本書有沒有講到 X」它撈得到——即使你當時沒劃線。
  • 教練：把你散落的永久卡攤開、排好、標張力與缺口——攤開你的材料，不替你寫（🚧 紅線）。

兩條複利曲線（分清楚很重要）

  1. 領域知識複利（wiki）：關於主題知道了什麼。每個來源、每次查詢都長。這條要架構化——wiki / Outputs / log。
  2. 「它越來越懂你」複利：靠它每次開工讀你的具體痕跡（log.md、👍/👎、fleeting、尤其你的永久卡＝你最高解析度的聲音）重建對你的理解——不自建偏好引擎（記憶引擎交模型底層，見 handoff §8「你要存的是領域內容，不是記憶引擎」）。

關鍵收尾：寫永久卡（紅線那側、最費神的人類工作）同時做兩件事——既是你的知識複利，也是在教 AI 你的聲音。兩條複利曲線靠同一個動作餵養。

write-back 原則 + 儲存四層

  • 寫回的是「蒸餾後的答案」，不是原始對話（避免被動 append-log 反模式 + prompt-injection 攻擊面）。
  • 每筆 write-back 帶 provenance（author: agent_query、from query [date]、citation）。
  • query 答案寫進 AI wiki 層（Outputs / Concepts），永不自動寫 KB/Permanent/（🚧 紅線）；想當自己的理解 → 你 card 它（Phase 4）。
  • 儲存四層：① KB/log.md（帳本，一行/互動，greppable）② KB/Wiki/Outputs/{slug}.md（有份量答案；需復活此資料夾，ADR-028 曾刪）③ 就地更新既有 Concept/Source（小洞見，避免 page explosion）④ 回饋 sidecar（👍/👎 訊號，非 wiki 內容）。

待拍板（互動與複利）

  • write-back 主動度：確認式（AI 問你才存，pilot 建議；log 一律寫）vs 自動。
  • 是否復活 KB/Wiki/Outputs/ 當寫回的家，還是只併進既有 Concept 頁。
