## 3. 第一波計分：已確認的最小範圍

對外語意不能寫成「發文就賺分」。正確規則是：

| 行為 | XP／海里 | 裁決 |
|---|---:|---|
| 發文行為本身 | **0** | 自己可以生成，不能用數量刷分 |
| 貼文收到他人按讚 | **+10** | 第一波已入帳 |
| 貼文收到不同會員留言 | **+30** | 第一波已入帳；同文同人一次 |
| 貼文被他人收藏 | **+100** | 第一波已入帳 |
| 挑戰打卡 | 暫不計分 | 挑戰尚未開始，現在不必特別做「停止入帳」 |
| 影片觀看 | 暫不計分 | 延後；不要因為事件 0 筆就宣稱橋接完成或壞掉 |
| 課程／完課／測驗 | 後續再設計 | 目前程式舊值暫時留著即可 |

第一波 `SanjiConfig.scored_sources` 維持現況：

```text
like_received / comment_received / bookmark_received
```

不要為了「挑戰與課程延後」新增額外阻擋邏輯；它們本來就不在第一波 scored allowlist。

## 4. 產品詞彙：不要再把位階、稱號、徽章混成同一件事

| 詞 | 正確語意 | Profile 中的角色 |
|---|---|---|
| **島** | 生涯里程抵達的位置；16 級 | 航海日誌的目前位置與下一站進度 |
| **位階** | 隨航程提升的階級性 Status | 固定顯示目前最高位階；會員不能任意選 |
| **成就稱號** | 因特定事蹟取得、非階級性的稱號 | 會員可選一個放在姓名旁展示 |
| **徽章** | 一次取得、永久收藏的視覺物件 | 集中在徽章收藏區；不是位階本身 |
| **Benefit** | 隨位階／條件取得的 Access 或 Power | 不應和徽章收藏混在同一欄 |

已確認的關係：

- **每個可展示的稱號都應有一枚對應徽章**，讓它能存在收藏中。
- **不是每一枚徽章都能拿來當稱號。**「出航」「進入偉大航路」可以只是徽章。
- SAPS 分析上，徽章可以被歸為 Status 類獎勵；但產品 UI 上，**徽章收藏與階級位階必須分開**。
- 島嶼 Icon 是航海圖的定位符號，**不是徽章**。不要拿目前 16 枚 Icon 直接當 badge system。
- 「船長」是社群互稱／身份軌，不是位階名稱。

## 6. SAPS benefit：目前只留下簡單、真的有價值的東西

框架名稱用 **SAPS**：Status / Access / Power / Stuff。分析時可以四欄列出，但會員端不需要看到框架術語。

### 6.1 兩種取得方式

1. **隨航行前進解鎖、事前看得見**：島、位階、重要 Access。
2. **隨機獲得或參加活動得到**：成就稱號、驚喜徽章、挑戰／活動紀念。

### 6.2 已確認的 benefit 方向

| SAPS | 現在保留的東西 | 備註 |
|---|---|---|
| **Status** | 五段位階；成就稱號；對應徽章 | 位階與其他 badge 在 UI 分開 |
| **Access** | 「最惡世代」解鎖實體聚會優先報名；「王下七武海」解鎖與艦長 1 on 1 | 稀有稱號才配珍貴 Access；1 on 1 的 60 分鐘／一生一次沿用舊案，但正式公告前再確認容量 |
| **Power** | 每月直播主題的提案與投票 | **第一版是所有會員的基本權利，不綁等級、不做票券配額** |
| **Stuff** | 第一波沒有 | 不用實體物撐福利梯；成本、物流與海外會員不公平 |

### 6.3 已明確拿掉，不可從舊 master plan 復活

- 「三級玩法導覽」／Sanji 分級導覽
- Q&A／QA 優先
- 新內容提前 48 小時
- Beta／新功能先行體驗
- 活動保留席／年度實體活動保留席
- 艦隊評議席
- 與艦長共同設計一季挑戰
- 共同定義 final legacy
- 名字永刻艦隊史及任何相似的空泛「史冊」敘事
- 把「稱號展示欄開通」本身包裝成 benefit

原則是：**越難得的位階，才配越珍貴的 Access**；不能每座島硬塞一個沒人懂、也沒有營運方案的福利。

### 6.4 尚未定案

- 除「最惡世代」「王下七武海」外，其他位階是否要有 benefit。
- 實體聚會優先報名的名額、期限與執行方式。
- 1 on 1 的容量、預約方式與是否確定「每人一生一次」。
- 季度挑戰主題投票是否也完全普及；目前明確普及的是**每月直播主題**。
- 高階會員主持讀書會／主辦聚會的資格是否保留。

## 7. 每月直播提案與投票：最簡 v1

社群既有節奏：

- 每月一次讀書會直播。
- 每月一次身心健康主題直播。
- 每季另有挑戰，但挑戰機制目前延後。

已確認的最簡流程：

1. 每個會員都可以對**下下一個月**的主題投票，保留一個月讓修修準備。
2. 每月有一週提案期，在指定討論區收集提案。
3. **Sandy** 發文收集會員提案。
4. 提案期結束後，由 **Sanji** 從提案中挑出幾個選項進入投票。
5. 如果沒有人提案，修修可以主動提出候選。
6. v1 不做投票點數、每年 N 張票、會員方案差異化票權，也不做新 ledger。

未確認：讀書會書目與身心健康主題是否分成兩張 poll，或合併在同一個月度流程。

## 8. 新的登島儀式：修修錄製抵達影片

修修提出：會員抵達每一座島時，可以跳出一支由修修預錄、親自恭喜船長的影片。會員會因為想看
下一支影片而繼續前進。

這個方向很適合目前的設計：

- Status：艦長親自承認「你抵達了」。
- Access：影片只有抵達該島後才解鎖。
- Octalysis CD7：抵達前不知道完整內容，產生好奇心。
- 比硬湊 16 個營運 benefit 更可理解，也更有情感連結。

目前只是**方向成立，尚未設計或實作**。以下是討論中的建議，不是修修已逐條核准的 spec：

- 每島一支 30～60 秒預錄影片。
- 第一次抵達自動出現，看完收進航海日誌，可重播。
- 抵達前只顯示「修修在這座島留了一段訊息」，不劇透內容。
- 每支影片包含：恭喜、這座島的成長意義、前往下一站前要記住的一句話。
- 需字幕與 transcript，但可在解鎖後才顯示。

## 10. Icon 設計系統與逐枚驗收紀錄

### 10.1 不可破壞的視覺規則

- `viewBox="0 0 24 24"`
- `fill="none"`
- 主線 `stroke="currentColor"`
- `stroke-width="1.55"`
- `stroke-linecap="round"` / `stroke-linejoin="round"`
- canonical orange：`#e98965`
- 橘色只作線、點或一個小記號，不做大面積 fill。
- 同時檢查 72px、36px、24px，以及 light／dark marker。

## 13. 八角框架／SAPS review 後保留的設計原則

這輪沒有接受「為了填滿每一格而發明 benefit」。保留的原則是：

1. **他人驗證優先**：獎勵被認可的價值，不獎勵自己能大量生成的數量。
2. **Status 要可見且有稀缺性**：位階、成就稱號與 badge 必須在 Profile 看得到。
3. **Access 要真的珍貴**：實體聚會優先、艦長 1 on 1 只放在難得位階。
4. **Power 不等於剝奪基本權利**：月度提案與投票先給全員，不用故意鎖住再還給會員。
5. **Stuff 最弱**：第一波不靠贈品；也不把物流成本寫成長期承諾。
6. **里程是成長年輪，不是生涯排行榜**：新人不必在數學上追老會員。
7. **White Hat 為主**：使命、成長、社交、創造；避免用焦慮、掉級與懲罰逼回訪。
8. **休息也是航程的一部分**：香波地補上「暫停、修練、重新集合」，很符合身心健康品牌。
9. **Endgame 要走向貢獻與帶人**，但相關主持／主辦 benefit 尚未定稿，不要先實作。
