## 1. 最重要的工作方式

1. **一次只做一件事，絕不平行。** 不要同時改計分、UI、福利與 icon。
2. 每完成一個小步驟都 render 給修修看，等明確驗收才繼續。
3. 不能把「候選」寫成「定稿」，不能把「定稿」自行改回候選。
4. 主倉庫 `E:\nakama` 是 control plane；任何寫檔都在獨立 sibling worktree。
5. 不要因為文件看起來完整，就自行做 PR、部署或改 production code。
6. 每一枚島嶼 icon 必須單獨 review；同一枚可比較 A/B，但不能順便做下一枚。

**這份交接寫完時唯一待處理的 icon 是蛋糕島（Lv.13）的最後驗收。**

## 3. 第一波計分：只保留他人驗證的貼文互動

對外語意要講清楚：得分的條件是**被別人認可**，不是發文本身。

| 事件 | XP／海里 | 狀態 |
|---|---:|---|
| 自己發文 | 0 | 不給分；避免自我生成刷分 |
| 貼文收到他人按讚 | +10 | 第一波 |
| 貼文收到他人留言 | +30 | 第一波 |
| 貼文被他人收藏 | +100 | 第一波 |
| 挑戰打卡 | 暫不計分 | 挑戰尚未開始；不必另做「停止入帳」 |
| 影片觀看 | 暫不計分 | 延後 |
| 課程／完課／測驗 | 後續再設計 | 目前舊程式數字暫時不動 |

第一波 `SanjiConfig.scored_sources` 的方向只有：

```text
like_received / comment_received / bookmark_received
```

既有憲法仍有效：規則只在 `agents/sanji/rules.py`、規則改版不回溯、冪等鍵不得改、門檻只准調低或插入。
但本輪**未授權**修改它們。

## 4. 產品詞彙：四件事不能混在一起

| 名稱 | 正確意義 | Profile 的角色 |
|---|---|---|
| 島 | 航程中抵達的地點；共 16 站 | 航海日誌顯示目前島與下一站進度 |
| 位階 | 隨航程前進的階級性 Status | 系統固定顯示的最高位階 |
| 成就稱號 | 因特定事蹟取得的非階級稱號 | 會員可選一個放在名字旁 |

- 不是每個 badge 都可以當稱號。

- 「船長」是社群互稱／身份軌，不是位階名稱。

已刪除、不可補回的位階名稱：**霸王色**（能力而非位階）、**傳說船長**（非原作且與身份軌混淆）。

## 5. SAPS benefit：目前保留的簡版

會員端不用看到 SAPS 術語，但設計時用它避免把所有東西混在一起。

| Status | Access | Power | Stuff |
|---|---|---|---|
| 五段位階（系統授予） | 最惡世代：實體聚會優先報名 | 每月直播主題提案與投票 | 第一波沒有實體物 |
| 成就稱號（會員可選一個展示） | 王下七武海：與艦長 1 on 1 | 所有會員都是基本權利，不綁等級、不做配額 | 不以物流／贈品硬湊福利 |
| 對應稱號 badge、一般收藏徽章 | 抵達島嶼後可看的修修恭喜影片（方向成立，尚未實作） | Sandy 收提案、Sanji 篩選投票選項 | |

已明確移除，不可從舊 master plan 復活：

- 三級玩法導覽、Q&A 優先、新內容提前 48 小時、Beta 先行體驗。
- 活動保留席、艦隊評議席、共同設計一季挑戰、共同定義 legacy、永刻艦隊史。
- 把「稱號展示欄」本身說成 benefit。

原則：難得的位階才配珍貴 Access；不要每座島硬塞一個沒營運內容的福利。

### 每月直播主題的最簡流程

- 每月各有一次讀書會直播、一次身心健康主題直播；每季另有挑戰，但挑戰延後。
- 所有會員可對**下下個月**主題投票，保留一個月準備期。
- 每月有一週提案期，在指定討論區收集。
- Sandy 發提案募集文；Sanji 從提案中選幾項進投票；沒人提案時由修修提出候選。
- v1 不做票券、點數、會員方案權重或新資料帳本。

### 登島影片方向

修修提出：每抵達一島，就跳出由修修錄製的恭喜影片；這是讓人期待下一站的情感回饋，
比硬湊 16 項福利更合理。方向已認可，但未寫腳本、未拍攝、未實作。

建議留作未來設計約束：影片第一次抵達時出現、日後可在航海日誌重播；公告和影片文案由修修親筆。

## 7. Icon 系統規格

所有地點 icon 都是航海圖定位符，不是徽章：

```text
viewBox="0 0 24 24"
fill="none"
stroke="currentColor"
stroke-width="1.55"
stroke-linecap="round"
stroke-linejoin="round"
```

- canonical orange：`#e98965`（PANTONE 165 PC）。
- 橘色只可作線、點或很小的意義記號，不能作大面積填色。
- 每枚都要看 72px、36px light、36px dark、24px。
- 圖形需易讀、對稱之處必須真的對稱；不要畫成完整小場景。
- UI 落地時再讀 `docs/design-system.md`，surface 繼承站台背景與文字變數。
