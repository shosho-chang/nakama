一個系統取代另一個系統時，**權威、血緣、資料模型通常會被仔細搬過去，手藝不會**。
設計語彙、定版配方、內容標準這些「怎麼做得好看」的知識，如果沒有人明確清點，
新系統會**重新發明**它們——而且因為發明的人不知道原本為什麼那樣做，會發明得比較差。

**驗收方式**：拿創意手冊／設計系統的元件清單，逐項對照新系統實作了什麼。三種結果都要抓：
① 手冊有、新系統沒有；② 手冊有、新系統自己重造了一份；③ 新系統有、手冊沒有（憑空發明）。

**Why**：2026-09-08 review 20260901 蘇予昕長精華。修修從「章節卡的字沒頭沒尾」一路問到
「我從來就不知道什麼是 Visual Effect」「Hero title 我記得之前沒那麼糟才對」。逐項對照
`.claude/skills/longform-cut/SKILL.md` 的長片視覺語彙之後：

| 手冊的元件 | ADR-066 的實作 |
|---|---|
| 滿版轉場卡 | 內嵌 HTML，與定版檔各一份（修了一份另一份還是壞的） |
| Hero 大字卡 | 自創 `compact_paper` 64px 置中壓臉（定版是 `punch_card_wide` tier1 96px 負空間） |
| 來賓名牌 | 自創 `identity_plaque` 36px 藥丸（定版是 `chapter_label_wide` 左下紙卡＋手繪橘豎筆觸） |
| Stock Video | ✅ 有帶過來 |
| 品牌 badge | **完全沒有** |
| 論文第一頁卡 | **完全沒有** |
| — | `visual_effect`：憑空發明，`.claude/skills/` 裡 grep 不到一次 |

七項裡兩項憑空發明、三項重造、兩項消失。而且**沒有設計就沒有規格**：`visual_effect`
在秒數上限表裡連條目都沒有，所以一張卡可以掛 9.77 秒。

同一晚還發現同構的三件事：內容標準（「卡片要總結整節」）沒帶過來、只剩格式規則；
policy 的門檻（B-roll 75 秒節奏）裝在管線尾端而該滿足它的 worker 從沒被告知；
`summary` 欄位上游寫了、註冊丟掉、store round-trip 又丟一次。

**How to apply**：
- 遷移或重寫時，**先列出舊系統的「手藝清單」**（設計 token、定版配方、內容標準、
  節奏規則），逐項確認去向。沒清點就等於預設會遺失。
- 看到新系統自己內嵌一份 HTML／樣式／版型時，先問「定版檔在哪」。兩份實作一定會漂。
- 使用者說「我不知道這是什麼」＝ 那個東西很可能不是他的，是系統發明的。查 git log
  找它第一次出現的 commit，通常就是遷移那一筆。
- 使用者說「我記得之前沒那麼糟」＝ 去把舊系統的產出翻出來對照，不要只信自己的判斷。
