修修 2026-07-28 裁決：**訪談逐字稿維持「一個字都不改」，不要 LLM 潤飾版。**

## 經過

`run_transcript_prose.py` 產出的稿子交付後，修修主動提議放寬：「我的目的不是要
讓它真的變成一字不差的逐字稿…或許可以讓 LLM 吃進整個段落，順一版完全符合原意
的對話出來，做最小的修改。」

我做了三段樣本 × 兩種強度給他挑：
- **A 版**：只准刪（贅詞、口吃重複），一個字都不准加 — 機械可驗證
- **B 版**：另外允許補少量連接詞、微調語序（實測 150 字只加 7 個字）

**兩版都被否決**：「我看 A、B 版都不太行，還是保留最原始的機械版就好。」

## 為什麼（日後有人再提案時看這裡）

1. **「只刪不加」可以機械證明，但保證不了意思沒被改。** A 版把「那可是很難」
   當贅詞刪掉，而下一句「**因為**哲學畢竟是論證為主的」解釋的正是「很難」——
   刪掉之後那個「因為」接到「各執己見」上，**因果被接到錯的地方**，而且讀起來
   完全通順所以看不出來。我的驗證給它 ✅（純刪除、零新增）。
   → 教訓：**找一個可以機械證明的東西，然後把它誤當成「沒有失真」的證明**，
   這個錯我在這條線上犯了兩次（第一次是可疑 cue 偵測，見 PR #1104）。

2. **潤飾會系統性抹掉講者的語氣。** B 版把「有些人**可能**主張物理論」寫成
   「有些人主張」——保留變斷言。單處很輕，一整集會累積成另一個人的口吻。
   同類：「這**個**可能性」→「這**些**」（破壞他自己的比喻）、「這個路」→
   「這條路」（改對了，但那不是他講的）。

3. 逐字稿的價值就在**它是證據**。要好讀的版本，那是另一種產物（訪談整理稿），
   不該蓋掉逐字層。

## 現在的定案

- `transcript_prose.md` = 逐字版。**標點可以改、字不可以改**——`run_transcript_punctuate.py`
  的語意標點 pass 仍然有效（它只搬標點，apply 會逐字驗證），A/B 那種會刪字的
  潤飾不做，**也沒有做成程式碼**。
- 想再開這條線的話，先看上面第 1 點：需要的不是更好的 prompt，是能擋住
  「刪除造成的語意漂移」的驗證方式，而字數／子序列比例都擋不住。
