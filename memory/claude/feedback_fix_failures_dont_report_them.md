多階段產線（Director → DP → visual review → 渲染）跑到一半失敗時，**自己修**：
診斷失敗原因 → 把診斷結果餵回去 → 重跑。上下游 agent 之間該協商就協商，
像真的團隊一樣。**不要每次一失敗就把狀況整理成報告丟回來問修修怎麼解決。**

**Why**：2026-09-07 蘇予昕長片線，DP 提案被引擎拒絕，我做了完整診斷、寫成漂亮的
報告、然後停下來等指示。連續幾輪都這樣。修修：「**你現在每一次一失敗就停下來問我
要怎麼解決，我覺得很困擾。**」

他要的是產線會自己收斂，不是每個中間失敗都變成一次 HITL。**失敗診斷得再漂亮，
只要沒有自己往下推，對他就是零價值——他要的是成品，不是失敗報告。**

**How to apply**：
- 中間環節失敗 → 診斷 → 自動重試（帶著診斷結果當回饋）→ 重試上限到了才回報。
- 下游 agent 做不到上游要求時，把問題送回上游 agent 重新給方向，不是送回修修。
- 回頭找他只有三種情況：UAT（成品要他看）、設計分叉（兩條路各有優缺點）、
  不可逆／破壞性操作。**技術性失敗不在其中。**
- 真的卡死要回報時，一併帶上「我試了什麼、為什麼還是不行」，不是只有現況描述。
