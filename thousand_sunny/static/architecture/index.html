Nakama Web UI 路徑架構
公開 / 內部 / 編輯 / 知識 四層分明

現有 web UI surfaces 散落在 root / bridge / brook / promotion-review / writing-assist / books / read / processing 等不同 prefix。提案：依「誰擁有 + 對誰看」分四層 + 一個 API 層，每層綁一個 design system token namespace，命名碰撞清掉。

v2 變更：經 multi-agent panel review（Codex GPT-5 + Gemini 2.5-pro，2026-05-19）。Codex 抓出 6 處事實錯誤、ADR-024/027 ownership 衝突、redirect chain bug；Gemini 提供 UX cascade、Open Graph、API as Layer 5、i18n 預留四項補強。完整 audit 在 docs/research/2026-05-19-{codex,gemini}-architecture-audit.md 與 integration-matrix.md。決策：Fork A（保留 agent-centric 修正 ownership + 套 Gemini UX patches）。

07 ux · cascade

UX cascade — 每個 rename 帶動的非 URL 變更

Gemini panel 指出「URL is not an island」。每個 route rename 必須同步處理 cascading UI elements，不能只動 router。

cascade · title Page title + breadcrumb + nav active state
每個 rename 同 PR 內必須更新：<title>、breadcrumb 文字（如 Home › Brook › Handoff）、Bridge hub 內的 nav 連結 label（templates/bridge/index.html:597-600 已 hard-link /brook/bridge）、sidebar active-state matcher。漏 update title cascade 就是 URL ≠ UI 不一致的 recipe for confusion。
cascade · sharing Open Graph 標籤給 /progress + /architecture
/progress 是 partner-shared 連結，主要透過 Slack / email unfurl。目前無 og:tags → unfurl preview generic。新增：og:title（具體標題不是「Nakama Progress」）、og:description、og:image（用 shosho logo）、og:locale="zh_TW" + og:locale:alternate="en_US"。
cascade · i18n hedge /zh/ /en/ path segment 預留
目前所有 URL 英文 only。Gemini 指出：未來 shosho.tw 若擴英文版內容，現在 hedge 成本零、未來避免大遷移。決策：**接受 hedge** — 不立刻加 /zh/ /en/，但 router 設計時保留這個 path-segment 的可能性（不要 URL pattern 設成貪婪match，不要硬編語言到 controller name）。
cascade · permission 未來 granular sharing 的路徑可行性
Gemini 警告：agent-centric path 在「分享單一 surface 給 guest collaborator」場景不自然。例如想分享一個 /brook/projects/{slug} 給合作者，permission 規則寫成「only sub-path /brook/projects/{slug}」比寫「only /writing/drafts/{slug}」更難讀。**接受為已知 constraint**：Fork A 選了 agent-centric，需 accept 此 trade-off — 未來如真需要 granular sharing，再考慮加 task-based alias。
08 migration · phased

遷移步驟（panel-revised）

不一次全做。每個 Phase 小範圍、可獨立驗證、舊路徑保留 301 redirect 一段時間以免 bookmark 失效。

phase 0 Prereqs（panel 新增）— 不可省的功課
Codex 強烈要求：marketing landing 前必須先做 prereqs，否則 Phase 1 ship 完會發現一堆 broken link。內容：(1) 寫 redirect alias 測試 fixture；(2) 掃 Bridge templates 對 /brook/bridge / /projects / /promotion-review / /writing-assist / /books 的硬寫連結（已知 templates/bridge/index.html:597-600 至少一處）；(3) 掃 JS fetch 對舊路徑的硬寫（static/book_reader.js 等）；(4) CSP allowlist update（middleware/csp.py:31 寫死 /books + /api/books）；(5) login next= URL 處理新舊路徑都接受。完成 prereqs 才能進 Phase 1。
phase 1+2 原子合併：marketing landing + Brook/Robin 重整（panel 合併）
Gemini 警告分階段做會產生「Phase 1 完但 Phase 2 還沒做」的 max inconsistency state — 編輯 surface 一半在舊路徑一半在新。合併成單一 atomic phase：
(a) 建 / Shosho marketing landing（取代 / → /brook/bridge redirect）
(b) Brook rename：/projects/{slug} → /brook/projects/{slug}、/brook/bridge → /brook/handoff（不是 /brook/context — Codex 否決 too generic）
(c) Robin rename（從 Brook 移過來）：/promotion-review/* → /robin/promotion/*、/writing-assist/{id} → /robin/writing-assist/{id}（per ADR-024/027 ownership）
(d) 處理 /brook/chat → /brook/bridge → /brook/handoff 三跳 redirect chain（collapse 成 /brook/chat 直接 → /brook/handoff）
(e) 同 PR 更新 title / breadcrumb / nav label / og:tags
Redirect 策略改：先 302/307 trial 一週看 logs → 確定無問題切 301 → **不自動刪**，單一 operator 場景永久保留代價極低（Codex 質疑 30-60 天刪除是 arbitrary）。
phase 3 Robin prefix 統一（local-only，無 partner / SEO 影響）
/（Robin enabled）+ /processing + /done + /review-summary,plan + /books/* → /robin/*。/read 保留 query-string 形式 — path-based migration 屬另一階段。順帶處理 robin 周邊 API endpoints。
phase 4 技術債清理 — Bridge tokens 抽出後再決定 namespace 命運
抽 --nk-* Bridge tokens 從 19 個 template 的 inline <style> 到 thousand_sunny/static/bridge/tokens.css。**Codex 提醒**：抽完 tokens 後才可評估 --nk-* 是「永久第三 namespace」還是「Shosho 的一個 mode」— 不要在抽 token 前就 lock 答案。刪除 deprecated /bridge/health。VPS 的 Robin family 503 改成 deliberate "local-only" placeholder page（per Codex Sec 5）。
